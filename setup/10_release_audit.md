# 10 공개 전 독립 감사

현재 프로젝트를 유지하고 README.md, AGENTS.md, docs/OWNER_INPUT.md, docs/SYSTEM_SPEC.md, docs/STATUS.md 및 실제 Git 상태를 먼저 확인하세요. 현재 단계만 진행하고 최신 공식 문서로 API·설정을 확인하세요. 실제 키를 읽어 출력하지 마세요. 완료 시 변경 파일, 실제 실행 명령과 결과, 미검증 사항, 다음 사용자 작업을 남기고 docs/STATUS.md를 갱신하세요. 다른 단계까지 무작정 진행하거나 구현되지 않은 기능을 완료로 보고하지 마세요.

현재 시스템을 만든 사람의 보고서만 신뢰하지 말고, 설계·실제 코드·계정 설정·실행 결과를 대조하세요. 코드 확인, 모의 시험, 실제 외부 실행을 구분합니다.

다음을 실제 검증 가능한 테스트로 만드세요: 자료 누락, 중복 ID, 계산 오류, UI 오류, 기존 콘텐츠 보존, 임의 HTML/XSS, 금지 경로 변경, 심볼릭 링크, 잘못된 job_id, 미로그인/다른 사용자, 위조·만료된 상태 갱신, API 실패, timeout, 취소, 중복 dispatch, 동시에 수정된 main, 승인 후 candidate 변경, 배포 실패, 롤백.

생성 코드 검사 환경에 키·쓰기 토큰·OIDC 상태권한이 없는지, public 로그/아티팩트/PR/배포물에 비공개 자료가 없는지 확인하세요. 브라우저 secret 문자열 검사와 사용자별 DB 접근 검사도 하세요. GitHub OIDC 신원만 맞으면 모든 job을 갱신할 수 있는 구조를 금지하세요.

Chromium/Firefox/WebKit 및 실제 사용할 기기를 구분해 검사하세요. 자동 접근성 검사만으로 접근성/학습 효과 검증 완료라고 하지 마세요.

AUTO_PUBLISH는 문자열 ‘false’도 정확히 false로 처리하고, 최종 게시 직전에 정책과 취소·최신 버전을 다시 확인합니다. 허용된 신규 콘텐츠만 자동 반영할 수 있고 시스템 변경·대규모 수정·자료 미확인은 사람 승인입니다. GitHub 필수 리뷰 정책과 충돌하면 보류하고 보호 규칙을 몰래 우회하지 않습니다.

정상 배포를 보존하고 일부러 실패시킨 뒤 복구를 시험하세요. 아티팩트 보존 기간과 만료 후 재빌드의 비동일 가능성을 명시하세요. 전체 롤백으로 이후 정상 콘텐츠가 사라지지 않게 비교하세요.

docs/RELEASE_AUDIT.md에 각 항목의 증거와 미검증 부분을 쓰세요. 중대한 미검증 항목이 남으면 자동 공개 활성화를 권하지 마세요. 선생님의 명시적 승인 전 유료·공개 설정을 바꾸지 마세요.
