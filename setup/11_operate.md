# 11 일상 관리와 점검

현재 프로젝트를 유지하고 README.md, AGENTS.md, docs/OWNER_INPUT.md, docs/SYSTEM_SPEC.md, docs/STATUS.md 및 실제 Git 상태를 먼저 확인하세요. 현재 단계만 진행하고 최신 공식 문서로 API·설정을 확인하세요. 실제 키를 읽어 출력하지 마세요. 완료 시 변경 파일, 실제 실행 명령과 결과, 미검증 사항, 다음 사용자 작업을 남기고 docs/STATUS.md를 갱신하세요. 다른 단계까지 무작정 진행하거나 구현되지 않은 기능을 완료로 보고하지 마세요.

현재 요청을 신규 추가/기존 수정/게시 중단/재공개/복구/상태 조회/시스템 변경 중 하나로 분류하세요. 이미 저장된 기본값과 대화 연결을 사용하고 애매한 대상만 확인하세요.

신규 콘텐츠는 기존 카드와 주소를 보존합니다. 수정은 대상 ID·이전 버전·변경 사유를 기록하고 재검사합니다. 중단은 카드 숨김만 하지 말고 기존 실행 주소를 점검 안내로 바꾸며, Git 원본·과거 이력의 공개 여부가 바뀌지 않음을 설명하세요.

관리 화면에서 자동 공개 중지·실행 취소·진행 확인·재시도·승인·복구를 제공합니다. 운영 설정 변경은 관리자 확인을 받습니다.

정기 링크/게시 상태 점검, 오류 신고 경로(학생 개인정보 입력 금지), 중복 오류 알림 제한, 의존성/Actions 업데이트 PR, 월별 사용량 확인, 학년도/교육과정 재검토, 로그/데이터 보존·백업·복구를 운영 문서에 넣으세요. 업데이트를 검사 없이 자동 병합하지 마세요.

모델과 라이브러리 교체는 기준 사례 묶음으로 재평가하고 버전을 기록하세요. 정상 작업과 실패 사례를 모두 보존하되 원문 음성·비밀 값·학생 자료를 저장하지 마세요.

실행한 변경과 현재 공개 버전, 남은 문제를 요약하고 docs/STATUS.md에 기록하세요.
