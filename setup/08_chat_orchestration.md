# 08 대화로 끝까지 실행

현재 프로젝트를 유지하고 README.md, AGENTS.md, docs/OWNER_INPUT.md, docs/SYSTEM_SPEC.md, docs/STATUS.md 및 실제 Git 상태를 먼저 확인하세요. 현재 단계만 진행하고 최신 공식 문서로 API·설정을 확인하세요. 실제 키를 읽어 출력하지 마세요. 완료 시 변경 파일, 실제 실행 명령과 결과, 미검증 사항, 다음 사용자 작업을 남기고 docs/STATUS.md를 갱신하세요. 다른 단계까지 무작정 진행하거나 구현되지 않은 기능을 완료로 보고하지 마세요.

이제 관리 채팅을 실제 작업 실행기에 연결하세요. 일상 사용자가 Actions 화면에 들어갈 필요가 없게 하세요.

자연어는 구조화된 요청으로 변환하고 create_simulation, revise_simulation, get_job_status, cancel_job, approve_release, withdraw_simulation 등 제한된 도구만 연결하세요. 실제 도구 이름/스키마/권한을 문서화하세요. 임의 셸·저장소·URL을 인자로 실행하지 마세요. URL 검색/가져오기는 SSRF·리다이렉트·비공개 주소·용량을 제한하세요.

대화 모델의 인자를 서버가 다시 검증하고, 사용자·콘텐츠 ID·대상 버전·허용 작업을 확인하세요. 학년도·디자인·공개 기준은 저장된 설정을 사용합니다. 이미 아는 내용을 반복 질문하지 말고, 핵심 정보가 없거나 수정 대상이 불명확한 때만 질문하세요.

job_id, 실제 실행 단계, 오류, 검토 근거, 검사, PR, 후보 결과, 승인, 게시 URL을 표시하세요. 진행률이나 검사 결과를 꾸며내지 마세요. 창을 닫아도 재접속으로 이어지고, 네트워크 재시도에서 같은 요청을 중복 실행하지 않아야 합니다. ‘방금 만든 것’은 conversation과 content/version으로 해석하세요.

공개 승인은 검사한 candidate hash/commit과 연결합니다. 승인 이후 변경되면 승인을 무효화하거나 재검사하세요. 신뢰된 검사 결과와 정책을 확인한 서버만 반영합니다. 실제 게시 주소 검사가 끝나야 published로 표시합니다. 후보 코드를 관리 origin에서 실행하지 마세요.

채팅으로 신규 제작→자료 확인→실제 AI 실행→PR→관리 화면 승인→병합→Pages 배포→실제 URL 확인까지 한 번 시험하세요. 그 다음 같은 대상 수정과 작업 취소도 시험하세요. 실패·미확인 경로를 구분해 보고하세요.
