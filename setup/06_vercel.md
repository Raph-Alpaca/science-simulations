# 06 관리 제작실 배포

현재 프로젝트를 유지하고 README.md, AGENTS.md, docs/OWNER_INPUT.md, docs/SYSTEM_SPEC.md, docs/STATUS.md 및 실제 Git 상태를 먼저 확인하세요. 현재 단계만 진행하고 최신 공식 문서로 API·설정을 확인하세요. 실제 키를 읽어 출력하지 마세요. 완료 시 변경 파일, 실제 실행 명령과 결과, 미검증 사항, 다음 사용자 작업을 남기고 docs/STATUS.md를 갱신하세요. 다른 단계까지 무작정 진행하거나 구현되지 않은 기능을 완료로 보고하지 마세요.

관리 앱만 Vercel에 배포할 준비를 하세요. 공개 자료실은 Pages 그대로 유지하고 저장소도 하나를 유지합니다.

같은 GitHub 저장소를 Import하고 Root Directory=apps/studio로 설정하는 과정을 설명하세요. 모노레포의 잠금 파일/공유 패키지/빌드 경로를 실제 구조에 맞춰 확인하세요. 콘텐츠만 바뀌는 일상 작업에서 불필요한 관리 앱 배포를 줄이되 보안 업데이트를 놓치지 않게 하세요.

.env.example과 실제 필요한 변수 목록을 일치시키세요. 서버 키에 NEXT_PUBLIC_ 접두사를 붙이지 마세요. 앱은 설정 누락을 이름으로 설명하되 실제 값을 출력하지 않게 하세요.

운영/Preview 환경을 구분하고 신뢰되지 않은 PR의 코드에 운영 Secret을 제공하지 마세요. 관리 앱의 환경 변수와 Supabase 로그인 URL 설정을 실제 주소에 맞추세요. 현재는 AI_EXECUTION_ENABLED=false, AUTO_PUBLISH=false입니다.

미로그인 API 차단, 허용 교사 로그인, 새로고침, 작업 복원, 로그에 키가 없는지 검사하세요. 시뮬레이션 후보 코드는 관리 앱 인증 origin에서 실행하지 않고, 별도 origin 또는 엄격한 격리 미리보기를 사용하세요.

실제 배포는 사용자 승인 후 진행하고, 실제 관리 URL·커밋·검사 결과·미검증 사항을 기록하세요.
