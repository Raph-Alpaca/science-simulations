# 04 GitHub와 Pages 연결

현재 프로젝트를 유지하고 README.md, AGENTS.md, docs/OWNER_INPUT.md, docs/SYSTEM_SPEC.md, docs/STATUS.md 및 실제 Git 상태를 먼저 확인하세요. 현재 단계만 진행하고 최신 공식 문서로 API·설정을 확인하세요. 실제 키를 읽어 출력하지 마세요. 완료 시 변경 파일, 실제 실행 명령과 결과, 미검증 사항, 다음 사용자 작업을 남기고 docs/STATUS.md를 갱신하세요. 다른 단계까지 무작정 진행하거나 구현되지 않은 기능을 완료로 보고하지 마세요.

현재 로컬 자료실을 GitHub 저장소 한 개와 Pages에 연결할 준비를 하세요. 실제 업로드/공개 전에 대상 저장소·공개 파일 목록·현재 검토 상태를 보여 주고 사용자 승인을 받으세요. 기존 저장소를 임의로 새 것으로 교체하지 마세요.

git status와 ignore 검사를 통해 .local, .env, 키, 교과서 원문, 개인 메모가 커밋되지 않는지 확인하세요. 이미 추적되는 파일과 과거 이력은 ignore만으로 보호되지 않음을 설명하세요.

VS Code Publish to GitHub와 Settings→Pages→Source: GitHub Actions를 제 운영체제/화면에 맞게 안내하세요. UI가 다르면 현재 공식 문서로 확인하세요. 저장소 공개 여부/요금제에 따른 기능 차이를 확인하세요.

공식 Pages 아티팩트 방식의 워크플로를 만들고, 검사한 커밋의 dist/catalog만 배포하세요. 승인되지 않은 시제품은 배포하지 마세요. trusted main의 검사 코드와 적절한 최소 권한을 사용하고, 외부 PR에 Secret이 노출되지 않게 하세요. Actions 버전은 검증한 전체 SHA와 버전 주석으로 관리합니다.

공개 후 홈페이지·개별 주소·새로고침·하위 경로·정적 파일을 실제 확인하세요. 배포 커밋과 실제 URL을 기록하세요. 저장소 업로드, 빌드 성공, 배포 성공, 게시 동작 확인을 서로 구분하세요. 이 단계는 AI 자동 제작을 켜지 않습니다.
