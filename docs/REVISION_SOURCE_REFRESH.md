# 수정 제작의 자료 확인 갱신

2026-10-16 로컬 구현·검증 완료. 이 후속 SQL은 운영 미적용이며 새 유료 작업·학생 게시를 실행하지 않았다.

기존 결과에서 수정 요청을 준비할 때 원래 자료 확인 기록이 만료되면 이전 입력을 그대로 되살려도 제작을 시작할 수 없었다. 이제 같은 자료에 새 원문 확인 기록이 있으면 그 기록만 새 수정 입력에 연결한다. 선생님은 확인 범위와 비용을 다시 검토하고 동의해야 한다.

## 유지하는 경계

- 원래 결과 파일, 콘텐츠 ID·주소, 요구사항, 자료 URL·제목·범위·요약, 교육과정과 검토 수준을 유지한다. 다른 자료로 교체하거나 확인 범위를 상위 수준으로 바꾸는 기능은 아니다.
- 서버의 신뢰 기록에서 완전한 최신 묶음을 읽었을 때만 context.sourcePreparation 한 필드를 갱신한다. 자료가 부족하면 원래 입력을 유지하고 보류 사유를 보여 준다. 브라우저가 권한 기록을 제공하지 않는다.
- 원래 후보·피드백·근거 해시와 계보의 head를 계속 대조한다. SQL도 변경 가능한 필드를 제한하고 최신 기록을 검증한다. 새 작업·새 호출 예약에서 다시 검사한다.
- 전송 결과가 끊겼을 때 같은 요청 ID는 저장된 입력을 그대로 돌려준다. 그 사이 자료가 바뀌어도 동의 바이트를 자동 교체하지 않는다. 갱신은 새 요청과 새 동의로 한다. 이미 접수된 요청은 기존 작업만 반환한다.
- SQL 준비 상태가 확인되지 않으면 자료 확인 기능이 켜진 제작실의 수정 기능을 제공하지 않는다. 기존 비활성 설정의 동작은 보존한다.

## DB 변경

검토용 `20261016003924_studio_revision_source_refresh.sql`: 기존 함수 read_revision_context와 assert_revision_ready 두 개 변경, revision_preparation_version 함수1개 추가. 테이블·컬럼·권한 범위 추가 없음. 모든 함수는 security invoker/빈 search_path이며 브라우저 역할에 실행 권한을 주지 않는다.

기존27개 테이블·자료 권한 기록을 보존한다. 작업/예산/게시 비활성과 진행 중 작업·미정산 호출 부재가 전제다. 잠금5초/문장30초, 재적용 거절, 단일 트랜잭션이다. 실제 운영 적용 전 최신 백업·격리 복원 리허설과 정확한 변경 범위 확인이 별도로 필요하다.

## 검증

- 갱신 서비스/SQL5개: 만료 기록 대체, 동일 계보/원본/새 동의, 응답 유실 뒤 기존 바이트 복원, 철회/위조/범위 변경 차단, 소비된 입력 중복, SQL 누락 시 비활성.
- 새 migration3개: 실제 전체 기반 SQL 위에서27개 데이터와 나머지 메타데이터/권한 보존, 의도한 기존 함수2개와 새 함수1개만 변경, 중간 실패 rollback·활성 상태 거절·재적용 거절.
- 기존 수정8개, 결과5개, 자료 접수5개 회귀 PASS. 합성 데이터이며 모델 호출은 없다.
- 빌드/타입 PASS. Chrome390/1440의 신규 갱신2개와 기존 수정2개 PASS: 새 동의/새로고침 복원/응답 유실/철회 후 차단/접근성/가로 넘침/기존 결과 비실행. 추가 유료 접수0. 검사 서버 종료.
- 복원 리허설의 새 객체 생성 계정을 운영과 맞춰 전체 메타데이터가 정확히 일치하는 검사1개 PASS.

최초 보존 검사는 피드백 생성 전후를 잘못 비교해1건 실패했고, 비교 기준을 갱신 준비 직전으로 수정했다. 새 브라우저 검사2개는 Next 안내 요소까지 선택한 locator를 좁힌 후 통과했다. 실패 기록은 보존했다. 이 후속 수정 경로의 네이티브 PostgreSQL 동시 연결 검사는 별도로 실행하지 않았으며 앞선 자료 접수/철회 경합6개 결과와 구분한다.
