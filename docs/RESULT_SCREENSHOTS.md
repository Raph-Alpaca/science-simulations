# 결과 화면 기록 — 로컬 구현

선생님은 결과 코드만으로 디자인을 판단하기 어렵다. 제작 실행기의 기존 브라우저 검사가 후보의 초기 화면을 390px·1440px 너비, 900px 높이로 촬영하고 제작실에서 필요한 화면만 열어 볼 수 있도록 연결한다. 이전 기록에 이미지가 없으면 그 사실을 표시한다. 캡처는 조작 가능한 미리보기나 과학·학습 검토를 대신하지 않는다.

## 연결과 한도

- 후보 파일을 실행하는 기존 격리 검사 안에서만 촬영한다. 생성 코드·HTML·SVG·외부 URL을 관리 화면에 삽입하지 않는다. 컨테이너 권한, 보안 필터, 네트워크, 자원·시간 제한은 유지한다.
- 이미지마다 최대 192KiB의 JPEG, 두 고정 너비, 높이 900px만 허용한다. 바이트 SHA256·JPEG 프레임 크기·정규 base64를 검증한다. 새 모델 호출은 없고 독립 검토·보완 모델 입력에서는 이미지 바이트를 제거한다.
- 검사 보고서의 해시에 이미지가 포함된다. 후보·입력·검사 기준 커밋·시도 번호와 기존 서명 보고 절차로 연결한다. 실행하지 않은 검사를 이미지로 통과시키지 않는다. 캡처 실패나 크기 초과는 이미지 없음으로 처리하고 실제 실행 검사 판정을 유지한다.
- 제작 검사 프로세스의 출력 한도만 64,000바이트에서 640,000바이트로 늘린다. 진단·게시 검사 출력 한도는 유지한다. 기존 HTTP·서명 전송·DB 기록 제한 안에서 저장한다. DB 스키마 변경은 없다.
- 결과 목록에는 크기·해시만 반환한다. `POST jobs/:id/result-screenshot`은 기존 교사 인증과 작업 소유권에 더해 상태 버전·입력 해시·후보 해시·근거 해시·시도·이미지 해시를 재확인한다. 쿠키에 따른 비공개/no-store 응답을 사용한다.
- 브라우저는 고정 JPEG 데이터만 메모리에 표시한다. 원본 파일을 다운로드하거나 브라우저 저장소에 보관하지 않는다. 크기 선택, 이미지 설명, 확대 대화상자, Escape 닫기를 제공한다.

## 검증 상태

실제 검토된 2D·3D 합성 화면의 로컬 Chromium 촬영은 두 너비 모두 통과했고 브라우저 종료를 확인했다. 계약·소유권·버전·기존 보고서·모델 입력·컨테이너/게시 경계 등 관련 39개 검사 최종 PASS, 빌드·타입 PASS, 실제 Chrome 390/1440 화면과 기존 결과 검토의 총5개 브라우저 검사 PASS다. 확대·Escape·초점 복귀·접근성·스크립트 비실행·브라우저 저장소 미보관을 확인했다.

초기 테스트에서 기존 결과 두 버전을 함께 펼치면 화면 영역 이름이 중복되는 접근성 오류2개가 발생했다. 영역 이름을 최초/수정 버전별로 구분해 해결했고 원래 실패 기록을 보존했다. 의존성 링크와 오프라인 캐시 부족으로 빌드 준비가 실패했으나 같은 잠금 파일의 기존 검증 의존성을 복사하고 이 작업 폴더 내부 패키지 링크를 복구했다. esbuild 파일 접근 제한에 실패했던 컨테이너/게시3개 검사도 동일 코드를 정상 권한으로 검사해 통과했다. 버전이나 잠금 파일은 바꾸지 않았다.

검사 증거는 `.local/evidence/screenshots`의 capture-result.json, unit-tests.log, unit-environment-recheck.log, publication-limit-final.log, build-result.json, browser-tests.log, browser-final.log다. 최초 실패와 최종 통과를 구분한다. 이 실행은 실제 운영 후보나 원격 Linux 검사 결과가 아니다.

현재 변경은 별도 로컬 작업 폴더의 시스템 기능이다. 공개 업로드·운영 배포·추가 유료 제작·학생용 게시를 수행하지 않았다. 이미 준비한 유전 2D 추가 제작의 승인 대상 소스를 이 변경으로 대체하지 않는다.

검토 단계 수정과 통합한 최종 소스에서 관련52개와 빌드·타입을 다시 통과했다. 브라우저 화면 코드와 촬영 코드는 앞선5개 검사 이후 바뀌지 않았다. 실제 유료 실행은 기존 승인 소스로 종료됐으며 새 기능에 대한 운영 후보의 화면 기록은 아직 없다.
