# 실제 게시 파일의 바이트 대조

2026-10-07 로컬 시스템 구현. 운영 DB·환경값·게시 워크플로는 변경하지 않았다. 제작실 API와 개인 에이전트에 연결하기 전의 공통 검사 모듈이다.

후속 구현: [정확한 게시 묶음과 승인 결합](RELEASE_ARTIFACTS.md)에 파일 보관·기존 콘텐츠 유지·게시 전 재대조를 추가했다. 아래43개 검사는 당시 이력이며 후속 전체 회귀는55개 통과다. 실제 원문 검토/사람 승인 발급과 운영 게시 서비스 연결은 여전히 남아 있다.

## 확인하는 것

`automation/publish/verify-artifact.mjs`는 검토한 정적 산출물의 파일 목록과 SHA-256을 받아 실제 공개 주소에서 내려오는 바이트와 비교한다. 목록 전체의 해시도 기존 자료실 빌드 규칙과 일치해야 한다. 목록은 호출 전에 복사하므로 검사 도중 호출자가 객체를 바꿔도 기준이 바뀌지 않는다.

공개 기준 주소는 기존 GitHub Pages 자료실로 고정했다. 경로 이탈, 임의 URL, 중복/대소문자 충돌, 파일·폴더 충돌, 숨김 경로, 허용하지 않은 확장자, 잘못 정렬한 목록을 요청 전에 거절한다. 사용자가 여는 디렉터리 주소와 명시적 `index.html`이 모두 같은 바이트인지 검사하고, 목록의 하위 경로·스크립트·스타일·이미지 등도 전부 대조한다.

TLS의 기본 인증서/호스트 검증을 유지하는 Node fetch를 사용한다. 인증정보 없이 GET만 요청하며 리다이렉트를 따라가지 않는다. HTTP 200, 정확한 응답 URL, 파일 종류에 맞는 MIME, 실제 스트림의 SHA-256을 확인한다. 단순 HTTP 200은 통과 조건의 일부일 뿐이다.

전체20초·요청당5초·최대100파일과 디렉터리 진입점1회·파일당2MiB·전체 수신10MiB 상한이다. 전체 용량에는 진입점의 중복 대조도 포함한다. 실패 즉시 종료하고 자동 재시도하지 않는다. 취소·시간 초과는 전송과 스트림에 전달하며, 전송 계층이 응답을 돌려주지 않는 경우에도 검사 호출의 대기를 제한한다. 오류에는 고정 사유 코드와 실패한 공개 경로만 남기고 응답 원문이나 전송 예외 문자열을 반환하지 않는다.

## 승인과의 관계

호출자는 파일 목록과 예상 해시를 **신뢰된 검토 산출물 저장소**에서 읽어야 한다. 생성 코드·모델·브라우저가 제출한 목록을 승인 증거로 받아서는 안 된다. 이 모듈은 출처 검토, 사람 승인, 저장소 신뢰성 또는 동시 배포 직렬화를 발급하지 않는다.

반환 기록의 scope는 `published_file_bytes`이며 runtime은 항상 `not_run`이다. 파일 일치는 실제 조작·과학적 정확성·학습 설계·교육과정/교과서 대조 또는 공개 경로에 추가 파일이 없다는 증거가 아니다. 검사 이후 서버 내용이 영구히 유지됨을 보증하지도 않는다. 전체 게시 서비스는 승인된 버전·배포 실행·검사 시점·실제 브라우저 동작 결과를 함께 결합한 뒤에만 작업을 `published`로 전환해야 한다.

현재 기존 자료실의 승인 발급자 부재 차단과 빈 콘텐츠 목록은 유지된다. 이 검사만 성공했다고 게시 승인이나 작업 상태를 만들지 않는다. 웹 제작실과 향후 개인 에이전트도 같은 게시 서비스의 결과를 읽어야 하며, 에이전트의 완료 발언을 검증 기록 대신 사용하지 않는다.
