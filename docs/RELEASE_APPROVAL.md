# 최종 버전의 게시 승인 저장

2026-10-13 로컬 구현·검사 기록이다. 운영 DB에 적용된 worker 기반 증분과 별개이며, 이 승인 SQL·환경 스위치는 운영에 적용하지 않았다. 실제 교육 콘텐츠를 승인하거나 게시한 기록이 아니다.

## 화면과 서버

제작 결과 화면에서 게시 준비 상태를 조회한다. 출처 원문 검토와 배포 파일 검증을 마친 준비 기록이 있어야 선생님에게 확인 체크와 승인 버튼을 제공한다. 결과 버전과 배포 버전을 함께 표시하며, 승인 저장 후에도 게시 완료라고 표시하지 않는다. 결과 코드와 원문을 관리 화면에서 실행하지 않는다.

로그인한 교사의 서버 세션으로 소유자를 확인한다. POST에는 기존 동일 출처 확인·입력 크기 제한을 적용하며, 요청 본문으로 교사 식별자·검토 근거·승인 시각을 지정할 수 없다. 원문 검토 주장과 모델의 통과 의견만으로 준비 기록을 만들 수 없다.

- GET `jobs/:jobId/publication-review`: 서버가 검증한 최신 준비/승인 요약. 원문·배포 파일·교사 식별자는 응답에 포함하지 않는다.
- POST `jobs/:jobId/publication-approval`: 정확한 reviewId/proposalHash, 중복 방지 ID, 명시적 확인을 받는다. DB가 실제 교사와 시각을 기록한다.
- POST `publication-approvals/:approvalId/revoke`: 게시에 사용되기 전 승인 철회. 반복 철회는 같은 결과를 반환한다.

새 승인은 `STUDIO_RELEASE_APPROVAL_ENABLED=true`일 때만 가능하다. 기본은 false다. 승인 SQL이 설치되면 이 스위치가 꺼져 있어도 기존 승인 조회와 철회는 가능하다. 실제 운영 환경값은 변경하지 않았다.

## 권위 있는 기록과 버전 결합

`supabase/proposals/studio_release_approval_v1.sql`은 검토용 제안이다. 준비 발급자용 release_baseline/release_reviews 테이블 2개, 기존 approvals의 버전/요청 연결, 서버 전용 함수와 잠금을 추가한다. 새 테이블은 RLS를 켜고 익명·브라우저 역할의 읽기/쓰기를 차단한다. 앱 service_role은 준비/기준 정보를 읽을 수 있지만 만들거나 고칠 수 없다. 기준 정보는 기본 비활성이며 초기 행을 만들지 않는다.

서버는 후보의 정확한 바이트, 입력·상태·실행 검사·독립 검토·원문 근거·전체 배포 파일·기준 자료실·잠금 파일·정책 버전을 대조한다. DB는 예산 → 교사 → 대화 → 작업 → 실행 기록 순서의 잠금 아래 현재 상태를 다시 확인한다. 수정 의견·메모 추가, 후속 결과, 기준 변경, 새 준비 기록, 대화 삭제 또는 준비 철회가 있으면 이전 승인은 현재 게시에 사용할 수 없다. 준비 기록은 철회 외에 수정·삭제하지 못한다.

한 준비 기록에 한 승인만 저장한다. 응답이 유실되어 같은 요청 ID로 재전송하면 같은 승인 기록을 반환하며, 그 사이 상태가 바뀌었다면 효력이 없음을 함께 반환한다. 철회된 승인을 재전송으로 되살리지 않는다. 브라우저에는 중복 방지 ID와 탐색 ID만 남기며 검토 의견 원문을 로컬 저장소에 보관하지 않는다.

공통 서비스와 응답은 개인 에이전트 연결에서도 재사용할 수 있다. 현재 브라우저 인증은 외부 에이전트 위임 인증을 대신하지 않으며, 에이전트가 교사 승인을 발급하는 기능은 없다.

## 로컬 검증과 실제 적용의 구분

- 승인 SQL/서비스 8개 포함 제작·비용·인증 회귀 51/51 통과. 앞선 결과/후속 수정 연결까지 21/21 통과 기록이 있다.
- 실제 Chrome의 390/1440 화면에서 승인 확인, 중복 클릭, 저장 후 응답 유실·재전송, 재접속, 수정 의견에 따른 무효화, 승인 중지 중 철회 확인. 새 승인 화면 2개와 기존 결과 화면 3개, 총5/5 통과. 접근성 위반0, 가로 넘침 없음, 관리 화면에서 후보 코드 실행 없음.
- 자료실·게시 파일 전체 단위 검사55/55, 실행 규격4/4 통과. 제작실 빌드 및 TypeScript 검사 통과. 배포 추적 파일7개에서 .local/.env/.git 및 esbuild 포함0개.
- 첫 빌드는 승인 검사 모듈의 전이 의존성 때문에 esbuild 실행 파일까지 번들링하려다 실패했다. 순수 카드/실행 입력 검사와 로컬 파일 저장 어댑터를 분리한 뒤 통과했다. 검사나 안전 조건을 제거하지 않았다.

모델 응답·원문 검토·사용자 인증·실행 결과는 합성 검사 자료다. 브라우저 조작은 실제 Chrome이며 SQL 서비스는 실제 로컬 DB를 사용한다. 이것으로 실제 교육 원문 확인, 운영 사용자 승인, 실제 AI 과금 또는 운영 게시를 통과로 간주하지 않는다. 최신 실제 PostgreSQL 동시성 결과와 보호된 증거 위치는 STATUS를 따른다.

## 남은 연결

신뢰된 원문 검토/준비 발급자, 승인된 전체 산출물의 기준 갱신, 원자적 게시 접수와 철회 경쟁 제어, 동일 바이트 업로드, 공개 URL의 파일·조작 확인 및 release 기록이 남아 있다. 게시 전 현재 승인을 다시 잠금 아래 확인해야 하며 이 승인 저장 함수만으로 외부 배포 경쟁이 해결되지는 않는다. 독립 origin의 조작 미리보기, 실제 제작 키와 운영 스위치 연결, 첫 원문 대조·유료 제작 시험도 남아 있다.
