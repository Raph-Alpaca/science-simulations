# 제작 전 자료 검토와 후보 검토

제작 전 교육과정 검토가 아직 만들지 않은 화면·기능의 실행 증거까지 요구하면 개발 단계에 도달할 수 없다. 역할 지침을 단계별로 나누고, 부족한 근거와 아직 수행할 차례가 아닌 검사를 구분한다.

| 단계 | 현재 판단할 내용 | 이후 확인할 내용 |
|---|---|---|
| 교육과정 자료 검토 | 확인한 부분과 요청 개념·학년·단원의 적합성 | 구현 기능·화면·완성된 학습 활동 |
| 교과 자료 검토 | 과학 개념·모형 가정·계산 도출·범위에 맞는 자료 | 계산 코드 실행·화면의 가정/한계 문구 |
| 학습 설계 | 목표·활동·상호작용·화면과 접근성 계획 생성 | 실제 구현·학생 사용 |
| 개발 | 계획과 요구사항에 따른 단일 콘텐츠 구현 | 독립 검토·격리 실행 검사 |
| 독립 후보 검토 | 정확한 후보·자료·설계·실제 검사 증거 대조 | 선생님의 최종 버전 승인·게시 확인 |

검토 범위는 승인된 입력의 sourcePreparation.reviewScope에서만 읽는다. 자유 문구나 모델 응답으로 낮추지 않는다. general_concepts에서는 공개 교육자료와의 개념 일치를 검토하며 선정 학교 교과서 일치는 미확인으로 남긴다. 이때 reviewer의 textbook 체크도 공개 교육자료에 대한 개념 검토를 뜻한다. selected_textbook은 해당 판본·쪽의 증거를 요구한다. 범위가 없는 과거 입력을 자동으로 일반 개념 범위로 바꾸지 않는다.

입력·응답·후보 계약과 통과 조건은 유지한다. 교육과정·과학 자료가 부족하거나 모델이 차단하면 그대로 중단한다. 문장을 보고 차단 사유를 지우거나 강제로 통과시키는 예외는 없다. 실제 실행 검사 미완료는 보류이며, 실패 후 최대2회 보완·최대9호출·기존 비용/시간 상한을 유지한다. 제작 전 검토가 지나갔다는 이유로 후보의 기능·디자인·접근성 검사를 생략하지 않는다.

새 호출 기록에는 rolePolicyVersion, reviewStage, reviewScope, instructionsHash를 추가한다. 서버는 네 항목 모두가 있을 때 승인된 원본 입력과 현재 정책으로 다시 계산해 일치 여부를 확인한다. 일부 항목만 있거나 위조된 범위/단계/해시는 거절한다. 기존 기록은 계속 읽을 수 있고 기존 worker의 기록 형식도 허용한다. 이 메타데이터 자체가 검토 품질이나 게시 권한을 증명하지는 않는다. 지침을 바꿀 때 정책 버전과 서버·실행기 소스를 함께 검토해야 한다.

로컬 합성 검사로 정상 순서, 실제 근거 부족/미실행 검사 차단, 범위 하향 시도 거부, 차단 출력 보존, 기존 결과 호환, 서버 전송·저장 경계를 확인한다. 모델을 호출하지 않은 검사이므로 새 지침을 실제 모델이 올바르게 따랐다는 증거는 아니다. 실제 유료 실행은 새 범위 승인과 해당 입력 제한을 준비한 다음 확인해야 한다.

최종 화면 기록 기능과 통합한 관련52개 검사 및 빌드·타입 PASS. 초기 연동에서는 새 감사 항목을 서버의 엄격한 필드 검사가 거절했다. 네 항목의 완전성, 신뢰된 입력에서 계산한 단계·범위·지침 해시 대조를 추가한 뒤 해결했다. 잘못된 단계/범위/버전/해시 및 일부 항목 누락을 실제 합성 HTTP·DB 경로로 거부하는 검사와 과거 형식 호환 검사를 함께 통과했다. 초기 실패 기록은 삭제하지 않았다.

## 필수 파일과 형식 보완

개발 요청에는 메타데이터 스키마와 함께 필수 meta.json, 신뢰된 콘텐츠 ID·학년·단원·교육과정, 허용 편집 상태를 명시한다. 파일이 누락되거나 메타데이터 형식/HTML 진입 파일이 잘못되면 그 출력은 후보로 등록하거나 실행하지 않는다. 원시 출력은 그대로 보존하고, 완전한 파일 묶음을 다시 반환하도록 같은 작업의 보완 기회를 사용한다.

형식 보완과 실행·내용 보완은 합쳐서 최대2회다. 총9호출·기존 시간/비용 한도를 늘리지 않는다. 수정에 필요한 원본을 다음 프롬프트 한도 안에 담지 못하면 잘라 보내지 않고 보류한다. 잘못된 경로, 다른 콘텐츠/학년/단원/교육과정, 자체 승인, 미등록 출처는 보완 대상으로 완화하지 않고 거절한다. 수정된 파일도 전체 계약과 이후 실제 검사·독립 검토를 모두 통과해야 한다.

생성 횟수와 격리 검사 번호를 따로 센다. 형식이 잘못된 출력은 검사 번호를 소모하지 않으며, 첫 유효 후보는 항상0번 검사에 전달한다. 실제 검사 workflow가0→1→2 순서로 기다리는 동안 형식 보완 때문에 대기가 막히지 않도록 한다. 합성 검사는 보완 횟수 공유·원시 출력 보존·검사 순서·권한/취소/크기 한도를 확인하며, 추가 유료 실행 성공을 대신하지 않는다.
