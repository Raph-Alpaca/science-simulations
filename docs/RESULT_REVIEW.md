# 제작 결과 조회와 버전에 묶인 의견

2026-10-05 로컬 구현. 운영 적용·실제 생성·게시 승인은 수행하지 않았다. 기본 `STUDIO_RESULT_REVIEW_ENABLED=false`이며 DB 버전 확인까지 통과해야 검토 화면이 나타난다.

## 화면과 API

실제 작업의 **결과·검토 보기**에서 결과 제목·요약·모형 가정, 교육과정/교과/설계의 개별 모델 의견, 최초 및 수정 결과의 실행 검사와 독립 검토, 기록된 비용을 확인한다. 이전 실패도 보존한다. 원문 근거 부족으로 파일 생성 전에 멈춘 경우에는 필요한 근거와 보류 이유를 표시한다.

`GET jobs/:id/result`는 현재 교사의 실제 작업만 조회하며 다른 사용자·비활성 교사·삭제 대화는 감춘다. DB의 한 SQL 문장으로 작업/worker/입력/증거/비용/의견을 같은 MVCC 스냅샷에서 읽는다. 서버는 원본 입력, 각 증거 본문, 연속 순번, 후보 manifest/개발자 출력, 실행 보고서의 SHA/검사 해시, 독립 검토의 순서와 후보를 재검증한다. 임의 pass 플래그를 그대로 보여 주는 방식이 아니다. 최종 JSON 요약은256KiB로 제한한다.

모델의 검토는 **AI 의견**, 실행 보고는 **별도 실행 검사**로 구분한다. 실제 원문 대조 증명·수업 적용 맥락·배포 파일·게시 승인 연결이 부족하면 공개 전 확인할 항목으로 남긴다. 현재 발표 가능한 배포 아티팩트와 원문 검증 연결이 없으므로 publication.eligible은false다. 원문/배포 근거 시스템을 연결한 뒤 그 권위 있는 기록으로 교체해야 하며 단순히 상수를true로 바꿀 수 없다.

`POST jobs/:id/result-file`은 화면에서 본 작업 상태·입력·후보·전체 증거 버전과 일치하는 파일만 JSON 텍스트로 반환한다. 경로는 검증된 후보 manifest에서 찾는다. 생성 HTML/JS는 React가 이스케이프한 코드 텍스트로 표시하고 iframe·script·object 등으로 삽입하지 않는다. 조작 가능한 별도 origin 미리보기는 아직 남아 있다.

## 검토 의견과 수정 요청

`POST jobs/:id/feedback`은 메모 또는 수정 요청을 저장한다. 입력은 clientRequestId, 정확한 네 가지 버전 값, 종류, 최대2000자 내용뿐이며 소유자는 서버가 결정한다. 생성 파일이 없으면 메모만 허용한다. 아직 진행 중인 작업에는 기록할 수 없다. 알려진 비밀값 형식과 로컬 비공개 경로는 거부한다. 이 패턴 검사는 완전한 개인정보 탐지기가 아니다.

새 `result_feedback` 테이블은 소유권 FK/RLS, 서비스 insert/select만 허용하며 브라우저 역할 접근·수정·삭제를 거부한다. RPC는 budget→teacher→conversation→job→worker 순서로 잠그고 상태 버전·입력 해시·최신 후보 해시·전체 증거 해시를 다시 확인한다. 동일 요청 ID/내용은 같은 영수증, 같은 ID의 다른 내용이나 낡은 버전은409다. 작업당20개 상한이며 상한 뒤에도 기존 영수증 재조회는 가능하다.

브라우저에는 요청 UUID와 내용 해시만 잠시 보존하며 의견 원문·후보 코드를 저장하지 않는다. 저장 응답을 잃으면 같은 요청으로 기존 기록을 확인한다. 저장해도 작업·모델 호출·승인·release를 생성하지 않는다. 수정 요청에 따라 기존 콘텐츠 ID를 유지하는 후속 제작 실행은 다음 연결 작업이다. 의견 기록을 실제 수정 완료나 게시 승인으로 표시하지 않는다.

## 검사

로컬 새5개/전체141개 단위·통합 검사 통과, production build/TypeScript 통과. 실제 서명된 합성 OIDC HTTP와 로컬 SQL로 생성/실행 보고/검토 증거를 쌓고, 검토 조회·버전 불일치·소유자 격리·비활성/삭제·본문 변조·허위승인 거부·중복 저장·불변 기록을 검사했다. 모델 의견과 실행 관찰은 합성 값이며 실제 AI/교육과정 검증이 아니다.

Chrome 새3개(390/1440px 결과와1440px 근거 부족) 통과/exit0, 23.2초. 이후 전체17개도 통과/exit0(1.1분), 검사 서버 종료까지 확인했다. 후보에 script와 모델 의견에 img/onerror 문자를 넣어 실행되지 않고 텍스트로 보이는지, 이전 초기화 실패 기록, 게시 요건 미충족, 응답 유실 후 같은 의견1건, 원문 브라우저 저장 없음, 새로고침 복원, axe 위반0·가로 넘침 없음을 확인했다.

첫 브라우저 검사는 Next의 숨은 route announcer도 선택한 strict locator 충돌과 option의 disabled 판정 방식으로 실패했다. 실제 알림을 선택하고 DOM disabled 속성을 확인하도록 수정했으며, 오류·비활성·중복 저장 assertion은 유지했다. 실패 추적은 `.local/evidence/worker/result-review-failure-6c54995e-6620-48f7-9a73-fb8d3d298bbc`에 보존했다.

첫 PostgreSQL17 실제 연결 검사21개는 모두 통과했지만 정리 확인이 시간 제한을 넘어 전체 exit1이었다. `.local/worker-pg17-input-af94961dcfbc4b33ab522e44b517065d/result.json`은 수정하지 않았다. 별도 cleanup-verification.json에서 pg_ctl status3/서버 없음·PID/임시 평문 암호 없음 확인을 보존했다. 검사 도구는 정리 관찰이 불확실할 때 같은 클러스터를 한 번 확인하도록 보완했다.

최종 새 PostgreSQL17 검사21개 PASS/exit0, 00:52:42~00:53:19 KST. `.local/worker-pg17-input-dd9b68b0629e41b0be517f1fa49bfd1b/result.json`: 현재9개 SQL 해시 일치, 모든 경쟁의 실제 Lock/차단 PID, stopped=true/stopCommandExit0, PID·임시 평문 암호 없음, 현재 사용자/SYSTEM 보호 ACL 확인. 실제 운영 DB와 암호는 사용하지 않았다.
