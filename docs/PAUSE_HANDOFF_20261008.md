## 작성 중이던 부분 — 아직 미검증

`supabase/proposals/studio_release_approval_v1.sql`은 승인 기록 저장을 위한 **검토용 초안**이다. 운영 migration에 포함하지 않았고 실제 SQL 적용·시험을 아직 하지 않았다. 기존 worker 기반 증분6개 파일의 승인 범위에도 포함하지 않는다.

초안 내용:

- 같은 요청의 중복 승인 방지, 새 피드백이나 새 검토 이후 오래된 승인 효력 차단, 승인 철회 기록. 실제 게시나 작업 상태 전환은 하지 않는다.
- 마지막 편집에서 기준/검토 변경 시 공통 budget 잠금을 잡는 트리거와 검토 기록 불변성(철회만 허용), 최신 검토 선택 조건을 추가했다. 동시성·권한·문법 검증은 미실행이다.

승인 저장용 서비스 모듈·새 API 연결·화면·전용 테스트는 아직 작성하지 않았다. 실제 원문 확인 기록 발급자, 분리된 도메인의 대화형 미리보기, 게시 잠금/정확한 바이트 배포, 게시 후 실행 확인도 남아 있다.

## 재개 순서

1. 이 중단 기록, 실제 Git 상태, 사용량, `.local/studio-worker-review-20261005/pause-20261008.json`의 해시를 확인한다. 기존 비밀값이나 비공개 원문을 채팅·로그에 출력하지 않는다.
2. 승인 SQL 초안과 fixture 변경을 검토한다. 실제 로컬 PGlite/필요 시 격리 PostgreSQL에서 적용 순서·권한·RLS·중복/철회·피드백/수정 무효화·기존 행 보존을 검사한다. 병렬 PGlite 호출을 물리적 DB 동시성 증거라고 하지 않는다. 운영 DB에는 실행하지 않는다.
3. 실제 인증 세션의 소유 교사ID를 사용하는 승인 서비스를 구현한다. 요청은 검토ID·제안 해시·중복 요청ID·명시적 확인으로 제한하고, 브라우저/모델의 승인JSON·원문 확인 판정을 신뢰하지 않는다. 저장된 후보·원문 근거·검사 결과를 재검증하고 DB 저장 직전 버전 조건도 재확인한다. 비활성 기본값과 안전한 철회를 유지한다.
4. 변경된 fixture에 의존하는 기존 결과/수정/worker 검사와 새 승인 검사를 수행한다. Windows 제한 계정의 상위 경로 realpath/esbuild EPERM은 이미 알려진 환경 문제이므로 필요한 검사는 실제 사용자 권한으로 요청하고 실패 증거는 보존한다. 앱 코드를 편집하기 전 `apps/studio/AGENTS.md`와 설치된 Next 문서를 따른다.
5. 신뢰된 원문 검토·승인 준비 발급, 안전한 미리보기와 게시 실행기를 연결한다. 실제 AI·운영 키 설정·학생용 게시 전에는 각각 준비된 구체적 범위와 권한을 확인한다. 월1만 원/약10건, 작업당1천 원·최대 자동 수정2회, 후속 수정 별도 비용 동의·접수 상한을 유지한다.

## 별도 대기 중인 운영 DB 승인

사용자에게 이미 요청했으나 **아직 답변받지 않은 범위**는 검증한6개 파일의 공개 PR·병합과 운영 science-studio DB의 단일 worker 기반 증분(테이블10개·함수37개·서버 역할 권한) 적용이다. 개인 에이전트 요구사항 답변은 이 승인이 아니다. 이전 PR #8 병합/진단 승인은 이미 사용 완료다.

`.local/studio-worker-review-20261005/worker-db-manifest.json`의6개 바이트는 보존한다. `docs/STATUS.md`, `docs/RESUME_HANDOFF.md`, `docs/WORKER_ROLLOUT.md`가 그 목록에 있으므로 이번 중단 기록은 별도 문서와 보호 checkpoint로 남겼다. 이 문서를 포함한 후속 로컬 변경은 승인 요청6개에 자동으로 포함되지 않는다.

운영 적용 승인 이후에도 최신 원격 상태·백업 유효성과 정확한 migration 해시를 다시 확인하고 gate를 닫은 채 진행한다. pending migration은 `20261007123947_studio_worker_foundation.sql` 하나이며 LF SHA256은 `d683387b09003dbe56a63e839d5991cfd3feffe50cc454730021bfa1c6a79a24`다. 새 승인 저장 proposal을 함께 적용하지 않는다.

실제 API 키/앱 키/신뢰 SHA 설정과 유료 제작은 아직 준비가 남아 있다. 비밀번호/키는 기존 보호 경로·숨김 입력을 사용하고 다시 채팅으로 받지 않는다. `.local`, `.env`, 비공개 원문·개인 메모·진단 평문은 공개 Git/PR/배포에 넣지 않는다.
