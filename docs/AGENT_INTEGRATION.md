# 개인 에이전트와 과학 시뮬레이션 제작실 연결

2026-10-13 추가: 웹 제작실의 [버전별 승인·철회 공통 서비스](RELEASE_APPROVAL.md)를 로컬 구현·검사했다. 별도 에이전트 인증과 게시 실행 연결은 아직 미구현이다.

2026-10-07 사용자 요청에 따른 설계 방향이다. 외부 에이전트 연결을 구현하거나 운영 권한을 활성화한 기록이 아니다.

같은 날 후속 로컬 구현: 향후 웹앱/에이전트가 공통으로 사용할 실제 게시 파일 대조 모듈을 추가했다. [검증 범위와 실제 빈 자료실 대조 결과](PUBLISHED_ARTIFACT_VERIFICATION.md)를 참고한다. 파일 일치와 전체 게시 완료를 구분하며, 에이전트 인증·위임/API 연결은 여전히 미구현이다.

## 목적과 확인된 결정

사용자는 나중에 개인 에이전트에서 과학 시뮬레이션 제작 시스템을 이용하려 한다. 제작실을 이 에이전트가 호출할 수 있는 전문 기능으로 제공하며 기존 웹앱도 함께 사용한다. 특정 에이전트 제품이나 새 인프라 구매는 결정하지 않았다.

2026-10-07 사용자 답변으로 다음을 확정했다. 두 질문은 답변 완료이며, 기반을 아직 정하지 않은 것은 진행을 막는 누락 정보가 아니다.

1. 기반: **아직 미정**. 특정 제품·전송 규격에 종속되지 않는 공통 서비스와 교체 가능한 연결 계층을 준비한다.
2. 위임: **제작·검토·수정은 자동으로 진행하고, 공개 게시 전 선생님이 승인한다. 선생님이 직접 수정·보완을 요청할 수도 있어야 한다.**

이 결정은 신규 결과와 후속 수정 결과에 모두 적용한다. 기존의 ‘초기 이후 조건부 자동 공개’ 구상은 현재 운영 요구사항에서 제외한다. 유료 제작은 기존 입력/이용 범위·비용 동의와 예산 정책을 따르며, 이번 확인은 운영 기능 활성화나 미승인 DB 적용을 뜻하지 않는다.

## 선생님의 검토와 수정·보완 흐름

과제 접수 → 자동 제작·독립 검토·보완 → 선생님 결과 확인 → 필요하면 수정·보완 요청 → 후속 제작·재검토 → 선생님 최종 승인 → 동일 결과물 게시·실제 주소 확인.

- 선생님은 웹 제작실이나 연결된 개인 에이전트를 통해 구체적인 수정·보완 의견을 전달한다. 대상은 제목만으로 추측하지 않고 작업 ID와 결과 버전으로 확인한다. 연결이 구현되기 전에는 에이전트에서 이미 사용할 수 있다고 표시하지 않는다.
- 수정·보완 요청과 검토 메모는 게시 승인이 아니다. 선생님이 최종 결과를 보고 내린 승인은 해당 후보·게시 파일·검토 근거 버전에 결합한다. 수정으로 버전이 바뀌면 이전 승인을 새 결과에 복사하지 않는다.
- 자동 검토의 보완은 작업당 최대2회다. 선생님의 후속 요청은 기존 별도 작업/비용 동의 흐름을 사용하고 월10,000원·월약10건과 콘텐츠당 후속20세대 상한 안에서 처리한다. 자동화가 무제한 반복을 뜻하지 않는다.
- 원래 과제·기존 후보·검토/실패 이력과 콘텐츠 ID를 보존한다. 수정본도 다시 독립 검토와 실행 검사를 거치고 선생님에게 제시한다. 이미 게시된 콘텐츠의 수정본은 새 승인·게시 확인을 마칠 때까지 기존 공개 버전을 대체하지 않는다.
- 에이전트가 승인 요청을 전달하는 경우에도 실제 선생님의 명시적 승인과 정확한 대상 버전을 신뢰할 수 있는 경로로 확인해야 한다. 에이전트나 모델이 선생님을 대신해 승인 내용을 만들어낼 수 없다.

현재 로컬 결과 화면에는 ‘수정 요청/검토 메모’, 해당 버전 의견 저장, ‘이 요청으로 수정 준비’와 후속 제작 연결이 있다. 코드의 버전 결합 및 비용 동의 흐름은 이 요구와 맞는다. 운영 기능 활성화, 에이전트 연결, 최종 게시 승인 서비스는 아직 남아 있다. 기존 구현/검사 범위는 [후속 수정 제작 연결](FOLLOWUP_REVISION.md)에 기록돼 있다. 이번 요구 확인에서는 실행 코드를 바꾸거나 기존 검사를 다시 실행하지 않았다.

## 유지할 연결 구조

웹 제작실 또는 개인 에이전트 → 인증·위임 확인 → 공통 제작 서비스 → 작업/예산 저장 → 분리된 제작·검토·실행 검사 → 선생님의 수정·보완 또는 최종 승인 → 게시 확인.

- 웹 화면에만 업무 규칙을 넣지 않는다. 두 진입점에서 같은 입력 확인·예약·검토·취소·버전 결합 규칙을 적용한다.
- 외부 요청에는 안정된 요청 식별자를 사용한다. 접수 결과로 작업 ID를 반환하고 이후 상태를 조회한다. 재전송·음성 명령 반복·연결 끊김이 새 과금으로 이어지지 않도록 중복을 판별한다.
- 상태 응답은 실제 진행 단계, 필요한 사용자 행동, 실패 사유 코드, 후보 버전, 비용 상태, 검토 근거 및 확인된 게시 URL을 구분한다. 제작 완료와 게시 완료를 다른 상태로 전달한다.
- 개인 에이전트가 종료돼도 서버의 작업 기록을 기준으로 재개한다. 실패·취소·비용 불확실 상태를 성공으로 바꾸거나 예약 금액을 임의 환불하지 않는다. 상태 조회 주기/횟수에도 상한을 둔다.
- 기능과 계약 버전을 조회하는 방법을 제공해 아직 없는 게시 기능 등을 에이전트가 호출 가능하다고 추정하지 않게 한다. 구체적인 전송 규격·인증 방식·알림 방식은 연결 대상이 정해지면 선택한다.

## 기능별 현재 기반과 추가 작업

| 기능 | 기존 코드에서 재사용할 기반 | 통합 시 추가할 것 |
|---|---|---|
| 과제 확인·제작 접수 | 입력 검토 서비스, 비용 동의, 중복 접수 방지 | 에이전트 요청을 검증된 입력으로 변환하고 위임 범위 확인 |
| 진행·결과 조회 | 작업 ID, 실행번호, 검토 증거와 비용 기록 | 원문 노출을 제한한 안정된 응답 계약, 재연결 |
| 수정·취소 | 버전 결합 의견, 후속 수정 계보, 취소 처리 | 정확한 대상 버전 확인, 후속 비용 동의 전달 |
| 승인·게시 | 승인 버전/해시 계약과 게시 검증 설계 | 선생님의 최종 승인 확인·발급, 동일 파일 게시, 실제 URL 확인. 에이전트에는 승인 생성 권한을 주지 않음 |

위 기존 코드는 일부 로컬 검증 단계이며 전체 운영 제작 연결이 완료됐다는 뜻이 아니다. 현재 실제 상태는 [STATUS](STATUS.md)를 따른다.

## 권한과 비용

에이전트는 사용자 대신 허용된 기능을 요청하는 주체로 식별한다. 사용자·호출 에이전트·위임 범위·요청 ID·작업/후보 버전·승인 주체를 추적하고 위임을 철회할 수 있어야 한다. 조회, 유료 제작 시작, 수정, 취소, 공개 게시를 같은 권한으로 묶지 않는다. 기존 브라우저 쿠키를 외부 에이전트에 복사하거나 내부 Actions 전용 worker 권한을 재사용하지 않는다.

비용은 웹앱과 모든 에이전트 호출을 합쳐 기존 월10,000원·월약10건 한도를 지킨다. 이 범위는 시뮬레이션 제작의 모델 비용이며 개인 에이전트 자체의 대화·음성·다른 도구 비용까지 새로 승인한 것은 아니다. 별도 비용은 통합 시 예산을 정한다.

개인 에이전트의 전체 대화·메모리를 자동으로 제작기에 보내지 않는다. 사용자가 확인한 과제와 이용 가능한 참고 자료만 전달한다. 후보 코드·외부 문서의 지시를 권한이나 게시 승인으로 받아들이지 않는다. 서버 비밀키·DB 관리자 권한·게시용 쓰기 토큰은 에이전트의 자유 입력이나 생성 콘텐츠에 제공하지 않는다.

## 현재 작업에 미치는 영향과 향후 확인

이번에는 요구사항을 문서에 반영한다. 현재 검토 중인 worker DB 증분은 그대로 보존한다. 별도의 에이전트 인증/위임 테이블이나 외부 API는 아직 추가하지 않는다. 연결 대상이 정해지면 필요한 증분을 검토한다. 이 요청을 대기 중인6개 파일 공개/병합·운영 DB 적용 승인 응답으로 해석하지 않는다.

향후 검증에서는 웹앱과 에이전트가 같은 작업을 조회하는지, 같은 요청을 반복해도 한 번만 접수/과금되는지, 권한 철회가 반영되는지, 오래된 후보에 대한 승인·수정이 거부되는지, 공유 월 예산이 강제되는지, 에이전트 재시작 후 실제 상태를 복원하는지 확인한다. 선생님의 수정·보완 요청으로 새 후보를 만들고 다시 검토를 받는 흐름, 수정 요청을 승인으로 오인하지 않는지, 바뀐 결과에 이전 승인을 재사용하지 않는지도 확인한다. 공개 게시 완료는 정확한 결과물의 실제 URL 검증 이후에만 반환한다.
