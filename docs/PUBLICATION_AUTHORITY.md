# 공개 전송 전 승인 소비

2026-10-14 로컬 검증. `studio_publication_authority_v1.sql`은 report proposal 다음의 검토안이며 운영 미적용이다. 새 `publication_deploy_enabled()` 기본값은 false다. 이 단계에는 실제 업로드·Pages 배포·게시 완료 전이나 새 워크플로 권한이 없다.

전송 준비를 시작하기 직전, github-pages 환경에 결합된 deploy OIDC로 `/api/publication/claim`을 호출한다. 같은 실행·첫 시도·검토 SHA·산출물·통과 보고서 해시와 최신 교사/작업/출처/준비/승인을 DB의 공통 잠금 아래 재확인한다. 유효할 때만 JWT 영수증과 승인 소비 기록을 함께 저장한다. 같은 승인·접수로 두 번째 소비는 새 토큰이더라도 거절하며, 일반 보고 이력 저장은 이 권한을 만들지 않는다.

승인 철회가 먼저 잠금을 얻으면 소비가 실패한다. 소비가 먼저 완료되면 일반 철회는 `PUBLICATION_STARTED`로 거부한다. 교사 화면은 승인 전에 이 경계를 설명하고, 소비 후 철회 버튼을 숨긴다. 오래 열린 화면에서 철회를 누르더라도 성공으로 표시하지 않는다. 아직 전송 전일 수 있으므로 문구는 **공개 전송 준비 시작**이며 게시 완료라고 표시하지 않는다. 수정·내리기는 별도의 후속 작업이다.

소비 후 출처 철회 사실은 계속 기록할 수 있다. 이미 시작한 외부 전송을 DB 철회와 원자적으로 취소할 수 있다고 주장하지 않는다. 같은 자료실 기준은 해당 승인에 대한 검증 완료 release가 기록되기 전까지 변경·삭제를 거부한다. 후속 완료 처리와 결과가 불확실한 경우의 관찰/조정은 아직 구현 중이며, 시간 경과·응답 유실로 소비 기록이나 전역 실행 슬롯을 자동 해제하지 않는다.

`claim-worker`는 신뢰된 호스트에서 암호화 파일과 암호화 보고서를 열고 같은 산출물·실행/승인 결합·실제 통과를 확인한다. 전송 시도 표식을 배타적으로 저장한 뒤 HTTP1회를 보낸다. 정상 소비 영수증을 받은 뒤에만 새 site 폴더에 같은 바이트를 풀어 전체 해시를 다시 확인한다. 거부·응답 유실·중복 실행은 평문 site를 만들지 않는다. 생성 코드는 실행하지 않는다. 파일 준비는 업로드나 게시 완료가 아니다.

클라이언트 전체60초·HTTP1회/25초·OIDC5초, 요청4KiB/응답8KiB, CLI55초 취소/60초 종료를 적용한다. DB 전체 영수증256개와 기존 파일/경로/10MiB 합계 제한을 유지한다. 공개 역할에 권한을 주지 않으며 새 권한 기록도 RLS·불변 트리거로 보호한다.
