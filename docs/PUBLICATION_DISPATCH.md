# 게시 검사 실행의 중복 접수 방지

2026-10-14 PR #12로 앱 배포를 완료했다. 운영 SQL·환경값·워크플로를 활성화하지 않았다. 이 기능은 게시 검사 실행 요청을 기록하는 구성 요소이며, Pages 배포나 게시 완료 기록을 만들지 않는다. 후속 실행 인증/파일 전달의 로컬 검증은 [PUBLICATION_ARTIFACT](PUBLICATION_ARTIFACT.md)를 따른다.

## 접수와 전송 경계

`studio_publication_dispatch_v1.sql`은 최종 교사 승인과 준비 기록에 연결한 실행 접수를 저장한다. 새 요청은 활성 교사, 삭제되지 않은 대화, 현재 결과·원문 근거·피드백·자료실 기준과 정확한 승인을 확인한다. 생성 코드나 브라우저 역할에는 읽기/쓰기 권한이 없다. 서버가 인증한 소유자만 서비스 호출에 전달한다. 활성화 함수의 기본값은 false다.

하나의 승인에는 하나의 접수만 생긴다. 같은 요청이나 새 요청 ID로 다시 클릭해도 기존 접수를 반환한다. 서로 다른 승인에 원래 저장된 요청 ID를 재사용하면 거부한다. 전체 자료실에는 동시에 하나의 미결 실행만 허용하며 작업당 접수 이력은20개로 제한한다.

외부 호출 전에 `ready → claimed`를 DB에 확정한다. 첫 호출만 전송 권한을 얻으며 이후 호출은 저장된 상태를 반환한다. 전송 결과와 DB 응답이 유실되거나 서버가 재시작되어도 claimed/uncertain을 시간 만료만으로 되돌리지 않는다. 재전송 대신 실제 실행 존재 여부를 확인하는 별도 복구가 필요하다. 상태를 직접 ready로 되돌리는 UPDATE도 DB 트리거가 거절한다.

`automation/publish/dispatch-service.mjs`는 별도 주입한 신뢰된 전송기를 최대1회 호출한다. 실행 전체45초, 개별 DB 요청5초, 마지막 결과 보존 최대5초로 제한한다. 제한은 검사에서 줄일 수만 있다. AbortSignal을 무시하는 연결도 호출 대기를 종료하고 불확실 상태를 보존한다. `failed`는 전송기가 외부 dispatch POST 전 실패임을 증명할 때만 사용할 수 있다. 예외나 알 수 없는 결과는 uncertain이다.

## 철회와 실제 게시의 구분

전송 권한을 받기 전 교사가 철회하거나 원문 근거가 바뀌면 접수를 cancelled로 바꾸고 외부 호출을 하지 않는다. 이미 전송한 검사 실행의 결과는 이후 철회·기능 중지와 관계없이 이력에 남긴다. 이 상태가 교사 승인을 되살리지는 않는다. 이후 게시 실행기는 실제 파일 공개 직전에 유효한 승인과 원문 근거를 다시 확인해야 한다.

submitted는 검사 워크플로 접수 확인일 뿐이며 모든 서비스 응답은 published=false다. 고정 GitHub 전송기와 인증된 제작실 API/상태 화면까지 연결했다. 후속 인증/파일 준비는 별도 단계이며 배포 권한 소비, 원격 결과 조정, 실제 공개 확인은 아직 없다. 따라서 운영 활성화나 게시 완료로 판정할 수 없다. 불확실한 실행은 전체 자료실 접수 자리를 유지하며 별도 조정 없이 새 게시를 받지 않는다.

## 서버와 화면

`GET/POST publication-approvals/:id/dispatch`는 기존 제작실 세션·Origin 검사·요청 크기 제한·private,no-store를 사용한다. POST는 clientRequestId만 받으며 소유자는 서버 세션에서 정한다. 조회는 활성화가 중지돼도 허용된 소유자에게만 제공한다. 현재 SQL이 없는 운영에서는 기능을 사용할 수 없다.

GitHub 전송기는 고정 저장소의 main과 `studio-publication.yml`만 대상으로 하며 입력은 DB에 저장된 publication_id 하나다. 제작 실행기의 기존 workflow/input은 유지한다. 별도 게시 활성화 스위치와 검토한 SHA가 필요하며 설치 토큰은 해당 저장소의 Actions write/Contents read만 허용한다. Pages 쓰기 권한은 없다. 요청 전체30초·개별 요청5초·응답128KiB·토큰 폐기2초를 적용하고 dispatch POST 이후 오류는 uncertain으로 남긴다. 실제 원격 전송은 실행하지 않았다.

교사는 승인 화면에서 기존 게시 요청 상태를 먼저 확인한 뒤 승인한 버전의 검사 요청을 접수할 수 있다. 조회/접수 응답이 유실되면 전송 버튼을 숨기고 상태 조회만 제공한다. 기존 요청은 일시 중지·승인 철회 후에도 조회할 수 있으며, 이력의 submitted를 게시 완료로 표시하지 않는다. 이 중간 단계 화면은 실제 게시 연결을 대신하지 않는다. 브라우저 저장소에는 승인/중복 방지 ID만 남기며 원문·키는 저장하지 않는다.
