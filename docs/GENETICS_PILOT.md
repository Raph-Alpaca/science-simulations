# 03 유전 시제품 — 로컬 미승인 초안

대상은 중3 생식과 유전, 활동은 우열·분리·독립이다. 교사 시연과 학생 조작으로 부모의 대립유전자 → 생식세포 → 수정 → 자손을 연결한다. 학년도·교육과정·교과서·독립의 법칙의 필수/보충/심화 위치는 미확인이다. 현재 입력으로 초안을 만들 수 있으므로 추가 필수 질문은 없었다.

## 근거와 역할

2026-09-13, 작업 ID `local-03-mendel`, 로컬 정책 `policy03-local-v1`. 아래는 실제 native_subagent 실행의 결과 요약이며 역할극이나 자동 승인 기록이 아니다. 역할 지침은 automation/roles를 읽었다. 제작자는 콘텐츠 폴더만 변경하며 공통 미리보기·검사·문서 작업은 주 에이전트가 담당한다. 이 세션의 경로 지시와 변경 해시 점검은 향후 원격 실행기의 OS 권한 격리가 아니다.

교육과정/교과/설계 검토는 후보 제작 전 수행했으므로 후보 코드 검증이나 후보 해시 승인을 뜻하지 않는다. 후보에 대한 독립 검토와 실행 결과는 STATUS의 최종 기록을 따른다. 에이전트 토큰 사용량은 측정할 수 없어 추정하지 않는다. 재위임은 금지했으며 개발 동시 작업은 1개로 제한했다. 검토 역할은 읽기 전용이다.

독립 검토의 최종 추가 판정은 “로컬 시제품 범위에서 확인된 미해결 차단 오류 없음, 교육과정·교과서 needs_evidence”다. 후보 해시 `0991f70040900dab250e5d53191a7e0f06039b286817c74e7c34a7a7a82e5c4a`에 결합한다. 최초 fail 지적과 수정 뒤 추가 판정을 구분해 보존했다. 검토자는 HTML 보고서 내부 실행 결과를 직접 읽었지만 브라우저 테스트를 직접 재실행하지 않았다.

교과 검토자가 실제 접근한 참고는 [OpenStax Biology 2e 12.3](https://openstax.org/books/biology-2e/pages/12-3-laws-of-inheritance)의 우성/열성·분리·독립·연관·유전자 상호작용 절이다. 개념 대조만 수행했으며 원문·그림을 복제하거나 로컬 자산으로 가져오지 않았다. AI 처리·재배포 허용 여부는 미확인으로 유지한다. 이 참고는 한국 교육과정이나 선정 교과서를 대신하지 않는다. references/source_index.json의 전체 검토 상태를 일괄 승인으로 바꾸지 않았다.

## 모형·검사 기준

- 우열: RR×rr → Rr 100%. r은 남아 있으며 우성은 우수함·힘·집단 내 빈도가 아니다.
- 분리: RR/Rr/rr 부모 선택. 해당 유전자의 대립유전자 하나씩 생식세포에 전달된다. Rr×Rr의 이론은 RR:Rr:rr=1:2:1, 둥근:주름진=3:1이다.
- 독립: R/r 씨 모양, Y/y 씨 색깔. 서로 다른 염색체, 각각 완전 우성, 유전자 간 상호작용 없음이라는 모형이다. 여러 감수분열의 생식세포 집단에서 RY/Ry/rY/ry 각 1/4이며, 한 번의 감수분열마다 네 종류가 모두 생긴다고 묘사하지 않는다. RrYy×RrYy의 표현형 확률은 9/16·3/16·3/16·1/16이다.
- 이론적 확률과 관찰 개수·빈도를 분리한다. 표본을 이론 비율에 맞추지 않으며, 표본 증가마다 오차가 반드시 줄어든다고 설명하지 않는다.
- 브라우저의 난수는 교육용 모의 표본이다. 실제 완두 재배 실험·학습 효과 검증과 구분한다. 테스트에서만 재현 가능한 RNG와 경계 RNG를 주입한다. [Math.random 공식 개발 문서](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Math/random)

## 시스템 작업과 공개 경계

로컬 미리보기는 automation/catalog/preview-genetics.mjs에서 실제 메타데이터·경로·링크 검사를 거친 뒤 `.local/catalog-tests/genetics-preview`에만 생성한다. 기존 자료실 UI에 해당 초안의 카드를 연결하고 미승인 배너를 표시한다. 실제 공개 빌더·승인 선택·신뢰 조건을 수정하거나 가짜 승인을 만들지 않는다. dist/catalog는 승인 콘텐츠 0개를 유지해야 하며 기존 회귀 검사가 이를 확인한다.

새 의존성·외부 API·로그인·개인정보 저장은 추가하지 않는다. 기존 고정 의존성을 사용한다. 콘텐츠 검사, 계산 단위 검사, 별도 Playwright 시제품 검사와 기존 자료실 검사를 각각 실행한다. 코드 수정·재검사는 최대 2회이며 실패 이력은 남긴다.
