# 검토한 파일을 그대로 게시하기 위한 묶음

2026-10-13 추가: 순수 묶음/승인 검사는 artifact-bundle.mjs, 보호 폴더의 파일 저장·재대조는 artifact-storage.mjs로 분리했다. 웹 승인 서비스는 빌드 도구나 로컬 저장 어댑터를 불러오지 않는다. [승인 저장 SQL·화면](RELEASE_APPROVAL.md)의 로컬 검증도 추가했다.

2026-10-07 로컬 구현·검사 기록. 실제 승인 발급, 운영 DB 적용, Git 업로드, 학생용 콘텐츠 게시를 수행한 기록은 아니다.

## 해결한 연결 문제

제작기의 후보는 `draft` 또는 `in_review` 메타데이터를 갖는다. 기존 게시 검사의 `ready` 요구에 맞추려고 승인 직전에 파일을 수정하면 후보 해시가 달라져 앞선 검토·실행 검사와 연결할 수 없었다.

새 v2 승인 검사는 편집 상태가 draft/in_review/ready인 후보의 **검토 당시 바이트를 그대로 유지**한다. 승인 권한은 신뢰된 외부 승인과 교육과정·교과서·과학 원문 검토 묶음, 권리와 여섯 검사에서 얻는다. withdrawn은 거부하며 v1의 ready/학년도 조건은 그대로다. 메타데이터의 상태가 스스로 게시를 허용하지 않는다. 운영 `productionInputs`는 여전히 신뢰된 발급자 부재로 콘텐츠를 선택하지 않는다.

## 준비·보관·대조

`automation/publish/artifact-bundle.mjs`는 다음 연결을 제공한다.

1. 기존에 신뢰된 자료실 전체 산출물을 파일별 실제 바이트로 읽어 묶는다. 정렬된 경로/바이트 해시 목록의 SHA-256을 기존 artifactHash 규칙과 일치시킨다. 텍스트 재인코딩으로 이미지나 글꼴이 바뀌지 않도록 내부 저장은 정규 base64를 사용한다.
2. 정확한 입력/후보/검사 기준 버전으로 검증한 후보 파일을 기존 전체 산출물에 넣는다. 카탈로그 코드·스타일·다른 콘텐츠 파일은 그대로 유지한다. 새 카드는 끝에 추가하고 수정 카드는 같은 위치에서 바꾼다. 대상 패키지는 새 후보 파일들로 교체해 빠진 옛 파일을 섞지 않는다. 기존 콘텐츠 ID와 진입점 주소 변경은 거절한다.
3. 작업 ID, 콘텐츠 ID, 입력·후보·기존 전체 산출물·새 산출물 해시, 검사 기준 커밋, 보완 회차, 진입점을 담은 제안과 proposalHash를 만든다. 모델 코드 실행, 새 의존성 설치, 도구 재빌드, 네트워크 요청은 하지 않는다.
4. `.local/release-artifacts/<새 UUID>/site/`에 정확한 파일만 저장한다. 묶음과 대조 기록은 site 밖에 두고 공개 출력에 섞지 않는다. 기존 저장본을 덮지 않는다. 작성 실패는 INCOMPLETE로 남기며 다시 쓰지 않는다. 저장된 바이트와 원래 해시를 실제 파일에서 재확인한다.
5. 게시 직전에는 저장본의 파일과 목록을 다시 읽는다. 이후에 파일이 변했거나 파일이 추가됐거나 불완전한 저장본이면 예전 기록으로 통과할 수 없다. 향후 게시 어댑터는 확인한 site 자체를 전송하고 다시 빌드하지 않아야 한다.

현재 전체 산출물은 기존 제한인100파일·10MiB·파일당2MiB 이내다. 경로 이탈·중복/대소문자 충돌·숨김 파일·허용하지 않은 종류·링크·과도한 크기·비정규 base64를 거절한다. 자료실 설정/카드/메타데이터/진입점의 일치도 확인한다. 기존 기준 해시와 다른 자료실을 임의로 새 기준으로 삼지 않는다.

## 선생님 승인과의 결합

`assertCatalogReleaseApproval`은 별도 신뢰 저장소에서 얻은 승인/현재 상태를 받아 검증한다. 승인은 teacher의 approve이고 해당 교사·작업·proposalHash에 결합되며 취소/무효화되지 않아야 한다. 수정 요청·메모·에이전트/모델의 승인 주장·다른 교사·미래 시각·다른 제안은 거부한다. 후보/입력/검사/원문 근거/정책/잠금 파일/기준 자료실 변경도 이전 승인과 호환되지 않는다.

**형식 필드만으로 실제 사람의 승인을 증명하지는 않는다.** 이 함수의 입력을 브라우저 요청 본문이나 모델 출력에서 직접 가져오면 안 된다. 서버의 인증·허용 교사·소유권·동의 화면을 거친 실제 승인 기록과 권위 있는 원문 검토 기록이 필요하다. 원문 근거를 발급하거나 선생님의 승인을 대신 만드는 기능은 이번에 추가하지 않았다.

동시 수정·승인 취소·다른 게시와의 경쟁은 향후 저장 서비스에서 원자적으로 처리해야 한다. 현재 함수는 전달받은 기준 버전의 일치를 검사하며 DB 트랜잭션이나 배포 직렬화 구현을 대신하지 않는다. 웹앱과 개인 에이전트는 이 게시 서비스를 공통으로 사용해야 한다. 실제 URL 파일 대조는 [게시 파일 검증기](PUBLISHED_ARTIFACT_VERIFICATION.md)와 연결한다.
