## 01단계 운영 규칙 — 설계 확정 / 기능 미구현

2026-09-13. 모든 기능은 아래 규칙에 맞춰 후속 단계에서 구현한다. 현재 공개/관리 URL·정상 커밋·외부 실행은 없다. 상태 전이와 데이터는 [DATA_CONTRACTS](DATA_CONTRACTS.md), 검사 증거는 [VERIFICATION_MATRIX](VERIFICATION_MATRIX.md)를 따른다.

### 작업 접수와 종료

일상 입력은 관리 제작실의 문자·음성이다. Actions 화면은 시험/비상용이다. 서버는 저장된 요구사항을 재사용하고, 대상·변경 내용·필수 근거가 없을 때만 질문한다. 입력 방식과 관계없이 같은 인증·소유권·상한·승인 계약을 사용한다.

요청은 추가/수정/조회/취소/중단/재공개/복구/시스템 변경으로 나눈다. 새 콘텐츠만 허용 ID를 예약하고, 수정은 ID·기준 버전·사유를 남긴다. 공통 코드·검사·권한·워크플로·새 의존성은 별도 시스템 작업이다. 개발자가 필요성을 설명한 뒤 해당 변경 범위로 검토하며 콘텐츠 작업이 자체 승인하지 못한다.

창을 닫아도 DB에 저장된 작업을 중단하지 않는다. 다시 열면 실제 상태와 증거를 조회한다. 같은 전송의 재시도는 같은 clientRequestId, 사용자가 명시적으로 재시도한 실패 작업은 새로운 jobId와 retryOfJobId로 연결한다. 원래 요청·실패 이력을 덮지 않고 비용 한도를 새로 검사한다. 늦게 도착한 콜백은 완료 상태를 되돌리지 않는다.

검사 실패는 해당 후보 공개를 막는다. 자동 수정은 최대 2회이며 소진되면 needs_review로 끝낸다. 자료 부족은 needs_input으로 보류한다. 재료나 버전이 바뀌면 새 snapshot과 후보 검사로 진행한다. 모델이 성공이라고 말해도 실제 실행·게시 증거가 없으면 완료가 아니다.

### 상한과 비용

| 정책 | 현재 결정 | 강제 위치·실행 조건 |
|---|---|---|
| AI_EXECUTION_ENABLED | false | 서버·실행기 양쪽. 누락/잘못된 값도 비활성 |
| AUTO_PUBLISH | false | 서버·게시기 양쪽. 문자열 false를 true로 취급 금지 |
| 동시 제작 | 1 | DB lease/claim + 실행기 concurrency |
| 자동 수정 | 최대 2회 | job repair_count 원자 증가; 재접속으로 초기화 금지 |
| 하루 작업 수·월 금액/통화·공급사 범위 | 미확인 | 첫 유료 실행 전 확정; 미설정이면 유료 실행 차단 |
| 작업 시간·역할별 호출/토큰·작업 금액 | 미확인 | 07에서 유한값과 실제 timeout/중단 검사 없으면 실행 차단 |
| 파일 수/종류/총용량·출처 가져오기 크기/시간/횟수 | 미확인 | 관련 로컬/원격 기능을 구현할 때 유한값 지정 및 초과 검사 |
| 녹음 길이/크기/호출 빈도·실시간 세션 길이 | 미확인 | 09/13 유료 시험 전 제한·취소·정리 검사 |

수정·재시도·검색·음성·하위 에이전트 사용량은 관련 job/세션에 합산한다. 실행 전 최대 사용량을 원자적으로 예약하고 종료 후 정산한다. 공급사 사용량 지연과 이미 진행 중인 호출을 고려해 내부 허용량을 관리한다. 대시보드 예산 알림은 강제 차단과 다르며 정확한 공급사 결제 상한이라고 약속하지 않는다. 월 비용 범위에는 포함할 서비스·통화·고정비·세금을 사용자가 결정하도록 남긴다.

### 승인·취소·비상정지

교사는 후보·검토·실행한 검사·미검증 사항·공개할 파일을 보고 해당 버전을 승인한다. 최초 공개는 사람 승인이다. 자동 공개는 10 감사와 실패·복구 검증 후 별도 명시적 설정 변경을 받은 경우에만 검증된 신규 콘텐츠로 제한한다. 자료 미확인·시스템 변경·대규모 수정은 자동 공개 대상이 아니다. GitHub 필수 리뷰/보호 정책을 우회하지 않는다.

취소는 먼저 cancel_requested를 저장하고, 실행기 중단을 요청하고, 실제 종료를 확인한 뒤 cancelled로 기록한다. 외부 요청이 이미 진행 중이면 확정되지 않은 종료를 주장하지 않는다. 병합/배포의 최종 부작용 직전에 취소·허용 정책·기준 버전을 다시 읽고 게시 lease와 상태 버전으로 경쟁을 제어한다. 이미 게시된 변경은 별도 중단/복구로 처리한다.

비상정지는 신규 접수/유료 dispatch/자동 공개를 막고 진행 중 작업 취소를 요청한다. 현재 정상 사이트는 유지한다. 비상정지 해제도 상태·비용·실패 원인을 확인하는 시스템 설정 변경이다. 실제 UI와 제어 API는 후속 구현 대상이다.

### 배포·중단·복구

검사한 아티팩트를 그대로 배포한다. published는 실제 공개 URL·버전 표식·정적 파일·기본 동작을 확인한 뒤 기록한다. 배포 오류나 게시 검사 실패는 기존 정상 release를 유지하거나 실제 외부 상태를 확인해 복구 작업을 만든다.

중단은 카드 숨김과 기존 URL의 안내 페이지를 함께 배포한다. public Git의 원본/과거 이력은 이 동작으로 비공개가 되지 않는다. 재공개는 마지막 승인 버전이라도 현재 정책·취소·아티팩트·공개 검사를 거친다.

복구는 문제 콘텐츠와 이후 정상 콘텐츠를 비교해 영향 범위를 먼저 정한다. 저장소 전체를 과거로 되돌려 나중에 추가된 정상 콘텐츠를 없애지 않는다. 보존된 정상 아티팩트를 우선하고, 만료로 재빌드하면 비동일 가능성을 기록하고 새 해시 검증·승인을 받는다. 이전 실패 release와 복구 release를 연결하며 실제 URL 확인까지 해야 복구 완료다.

### 정보 보호·보존·운영 점검

비공개 원문은 `.local/reference`, 개인 실행 증거는 `.local/evidence` 또는 접근 통제된 DB/저장소에 둔다. 공개 가능한 직접 작성 요약도 작성자가 공개/외부 AI 제공을 허용한 범위만 쓴다. 공개 로그/PR에는 개인정보 없는 상태·검사 요약만 남긴다. 첫 원격 제작에 비공개 교과서를 전달하지 않는다.

음성 원본은 기본 저장하지 않고 전사 후 또는 오류/취소 시 임시 데이터와 업로드를 정리한다. 작업 수행에 필요한 요약만 비공개 DB에 남긴다. 보존 기간은 미확인으로 두며 실데이터 수집 전에 대화·이벤트·검토·아티팩트·백업별 기간을 결정한다. 키/토큰/원본 음성은 백업 대상에 넣지 않는다. 삭제 작업은 관련 복구·승인 증거와의 관계를 검토하고 유료/공개/파괴적 영향이 있는 작업은 대상·범위를 확인한다.

정기 점검 주기는 운영 시작 전에 정한다. 링크/현재 공개 버전, 실패 작업, 월 사용량, 교육과정/학년도 변경, 의존성·Actions 업데이트를 점검한다. 오류 신고는 학생 개인정보 입력을 요구하지 않으며 동일 오류 알림은 중복 제한한다. 업데이트 PR은 기준 계산·권한·경로·브라우저 회귀 검사를 통과한 뒤 반영한다. 모델 교체도 기준 사례를 다시 평가한다.

키 노출 시 영향 서비스와 사용처를 확인해 해당 자격 증명을 폐기·교체하고 공개 로그·Git 이력·아티팩트의 노출 범위를 점검한다. 단순 .gitignore 추가나 현재 파일 삭제가 과거 노출을 해소했다고 보고하지 않는다. 비밀 값은 사고 보고서에도 넣지 않는다.

### 초보 사용자 안내 방식

현재 사용자가 수행할 외부 설정은 없다. 문서는 VS Code 왼쪽 탐색기에서 `docs`를 펼쳐 열 수 있다. 이후 명령은 상단 **터미널 → 새 터미널**의 Windows PowerShell에서 실행하며 npm은 `npm.cmd`로 안내한다. 실행 정책은 바꾸지 않는다.

04·05·06·07에서 외부 작업이 필요해질 때 실제 계정 화면과 최신 공식 문서로 메뉴 위치를 다시 확인한 뒤, 대상·입력 위치·결과 확인 방법을 함께 안내한다. 키를 채팅에 보내도록 요청하지 않는다. 예고된 메뉴나 URL을 이미 연결된 서비스라고 기록하지 않는다.
