# 제작 전 자료 확인 기록 연결

2026-10-16 로컬 구현·검사 완료. 운영 DB 적용·설정 활성화·실제 기록 발급·추가 유료 제작은 아직 하지 않았다. 첫 실제 제작이 자료 근거 부족으로 보류된 뒤, 실제 원문에서 확인한 범위를 다음 제작 입력과 연결하는 시스템 변경이다.

## 사용자에게 달라지는 점

제작 입력을 준비하면 각 자료의 원문 확인 범위, 한계, 확인일과 유효기한을 볼 수 있다. 교육과정·공개 교재·과학 참고 자료 중 빠진 종류, 미확인·만료·철회된 자료가 있으면 비용 동의와 제작 접수를 보류한다. 새 확인 기록을 연결하려면 새 입력을 준비하고 내용·비용에 다시 동의한다. 이미 접수된 작업은 같은 요청을 다시 보내도 추가 제작으로 만들지 않는다.

일반 개념 검토에서는 공개 교재를 사용할 수 있지만 **특정 학교 교과서 일치는 미확인**으로 표시한다. 자료의 일부를 확인한 기록은 시뮬레이션의 과학·교육과정·학습 설계 검토 통과나 게시 승인이 아니다. 후보 생성 뒤 독립 검토, 실제 동작 검사, 최대2회 보완, 교사의 최종 버전 승인은 계속 필요하다.

## 구현과 권한

- 계약: 소유자, 검토 수준, 교육과정 기준, 자료 종류·제목·주소·범위·정확한 자체 요약의 SHA256과 원문 확인 기록을 결합한다. 원문 해시·확인한 범위·한계·검토자 식별자·기한·AI 처리/요약 공개 권한을 검사한다. 브라우저나 모델의 verified 표시는 권한이 아니다.
- 저장소: studio.preparation_sources의 기존 기록은 변경·삭제할 수 없고 철회만 가능하다. 브라우저 역할은 접근할 수 없으며 앱/실행기 service_role도 읽기만 가능하다. 실제 원문 검토 후 별도 운영 절차로 발급한다. 검토자 식별자는 외부 전달 가능한 별칭을 사용하고 개인정보·원문·비밀값을 넣지 않는다.
- 입력 서비스: 신뢰 저장소에서 읽은 기록을 동의할 입력 바이트에 포함한다. 읽기 실패는 확인 완료로 취급하지 않는다. 일반 개념 중심이 현재 신규 입력의 기본 검토 수준이다. 특정 교과서 모드 선택 화면은 이번 범위에 없다.
- DB: 새 작업 접수와 새 API 비용 예약 직전에 현재 기록을 다시 대조한다. 자료 발급/철회와 같은 예산 잠금을 먼저 사용한다. 실패하면 해당 트랜잭션의 입력 소비·작업·예약을 모두 되돌린다. 이미 예약된 호출은 철회 전에 시작됐을 수 있어 회수할 수 없고, 중복 재전송 없이 기존 비용을 정산한다.
- 수정 요청: 원래 자료 기록을 유지하고 현재 상태를 재검사한다. 기록 만료/철회 후 **수정 계보 안에서 새 자료 기록으로 교체하는 흐름은 미구현**이며 보류한다. 이전 동의로 새 근거를 자동 승인하지 않는다.

## 검증한 범위

계약/저장소/입력 서비스 검사에서 위조·소유자 혼동·NULL·유효기한·철회·대체 기록·접수 원자성·중복 접수·예약 차단과 기존 정산을 확인했다. 합성 데이터 검사이며 실제 교육 자료를 검토한 기록이 아니다.

네이티브 PostgreSQL17에서 6개 상황을 별도 연결로 검사했다: 철회 먼저/접수 먼저, 반복 읽기 격리의 오래된 스냅샷, 동시 중복 접수, 철회 먼저/비용 예약 먼저. 실제 잠금 대기와 결과를 확인했고 서버를 종료했다. 최초 sandbox 실행 실패는 보존했으며 허용된 로컬 실행에서 성공했다. 운영 DB를 사용하지 않았다.

제작실 빌드·타입 검사 PASS. Chrome 390/1440에서 신규 자료 흐름2개와 기존 입력·수정4개, 총6개 브라우저 검사 PASS. 부족→새 자료 연결→새 동의→철회 후 차단, 접근성·가로 넘침을 확인했다. 실제 유료 시작 요청은0개다. worktree 의존성 부재로 첫 빌드는 실패했고 고정 package-lock 설치 후 통과했다. 검사 서버는 종료했다.

통합 migration 검사에서 기존26개 테이블의 데이터, 기존 함수 정의·권한 보존, 테이블1개/함수10개 추가, 모든 실행 기능 비활성, 중간 실패 시 전체 rollback과 재적용 거절을 확인했다. 새 source-preparation 백업 범위는27개 테이블을 포함한다. 백업 범위/기존 첫 실행 제한 회귀를 포함한12개 검사 PASS. 새 운영 백업·실제 복원본 적용 리허설은 별도로 수행해야 한다.

## 운영 적용 전 남은 절차

1. 정확한 공개 변경 목록과 SQL을 고정해 검토한다. 현재 새 SQL은 적용하지 않았다.
2. 최신 운영 읽기 전용 백업·격리 복원, 정확한 migration 적용 리허설과 권한·기존 데이터 보존을 확인한다.
3. 승인된 운영 적용 후에도 실행 스위치는 닫아 둔다. 앱의 STUDIO_SOURCE_PREPARATION_ENABLED는 기본false이고 활성화는 별도 단계다.
4. 실제 원문 범위와 자료 이용 권한을 확인한 기록을 발급한다. 기존 후보에 묶인 과거 부분 대조 기록을 새 권한으로 그대로 복사하지 않는다. 원문 해시는 무결성 표식이며 자체로 검토 완료 증거가 아니다.
5. 새 입력/동의와 제한된 실행 범위를 준비한다. 첫 유료1건의 승인은 이미 소진됐으며 새 제작을 자동 재시도하지 않는다. 후보·최종 승인·학생 게시의 실제 성공은 아직 미검증이다.
