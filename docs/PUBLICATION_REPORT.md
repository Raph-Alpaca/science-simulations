# 게시 검사 결과 저장

2026-10-14 로컬 구현·검증. `studio_publication_report_v1.sql`은 artifact proposal 뒤에 적용하는 검토안이며 운영 미적용이다. 게시 권한 소비·Pages 배포·학생용 공개 기능을 포함하지 않는다.

## 흐름과 경계

격리 검사가 만든 암호화 보고서를 별도 report job이 복호화한다. 실행/승인/검토/산출물 해시를 확인하고, 전용 report OIDC로 `/api/publication/check-report`에 한 번 전송한다. 검사에 실패해도 유효한 암호화 결과가 있으면 실패 이력을 저장한다. 컨테이너 생성 실패처럼 보고서가 없으면 저장 성공으로 처리하지 않는다.

서버는 DB의 불변 검토 문맥으로 보고서 전체 규격과 2D/3D 관찰을 재검증한다. 제출된 실행 번호·첫 실행·workflow SHA·후보/근거/기준/시도·산출물 해시·브라우저 종료를 확인한다. 보고서에는 정해진 `RUNTIME_*` 코드만 허용하며 원문 오류·소스·비밀값은 받지 않는다. 보고 역할로 파일을 읽거나 준비 역할로 결과를 쓰는 요청을 거부한다.

DB는 전역 잠금 아래 동일 문맥을 다시 확인하고 JWT 영수증과 불변 보고서를 함께 저장한다. 같은 JWT 재사용과 다른 보고서 덮어쓰기는 거부한다. 새 JWT로 동일 결과를 제출하면 최초 영수증을 반환하지만, 실행기는 자동으로 재전송하지 않는다. 전송 전에 배타적 `report-send.claim`을 남기므로 응답 유실 뒤에도 상태 관찰 없이 재실행하지 않는다. 보고서 저장은 승인 복원·소비, dispatch 종료, release 생성 또는 `published` 전이가 아니다. 승인 철회와 교사 비활성 이후에도 이미 측정된 결과를 이력으로 받을 수 있다.

## 실제 제한

- 클라이언트: HTTP 1회, OIDC 5초, 요청 25초, 전체 60초. 요청 20KB·보고서 16KiB·응답 8KiB. 리다이렉트와 자동 재시도 없음.
- DB: 게시 접수당 보고서 1개, 준비/보고 전체 OIDC 영수증 256개. 각 서버 RPC 10초, SQL 잠금 5초. 공개 역할 권한 없음, RLS 활성.
- Actions: 보고 job 4분, Contents 읽기와 전용 OIDC만 사용. 전달 키는 신뢰된 호스트에서만 사용한다. Pages 쓰기·DB 관리자 키·OpenAI 키는 부여하지 않는다. 기존 게시 기능 스위치 기본 비활성을 유지한다.
