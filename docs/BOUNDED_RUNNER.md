# 예산 안에서 실행하는 제작기 — 로컬 구현

2026-10-04. 운영 앱·Actions에 연결하지 않은 구현이다. 유료 API 호출, 실제 AI 제작·독립 검토, 생성 코드의 격리 브라우저 실행, 콘텐츠 PR·게시를 아직 실행하지 않았다.

## 확정 예산과 적용 범위

사용자 요구는 OpenAI API 월 최대 10,000원, 월 약 10건, 구체적인 2D/3D 시뮬레이션이다. `config/execution-budget.json`의 내부 환산은 2,000원/USD이며 월 USD5, 작업 USD0.5를 예약한다. 환율 시세가 아니며 세금·수수료를 포함한 공급사 원화 청구의 하드캡은 아니다. 실패·취소도 접수 건수에 포함하고 발생한 비용은 정산한다. 복잡한 3D의 품질이나 월 10건 성공을 보장하지 않는다.

한 작업은 교육과정 검토, 교과 검토, 학습 설계, 개발, 별도 문맥의 검토를 순서대로 호출한다. 최대 두 차례 개발·검토를 추가해 총 9회, 전체 20분, 각 공급사 요청 단계 90초다. 실제 비용 예약이 남은 예산을 넘으면 수정 횟수가 남아 있어도 중단한다. 단일 정책 행을 잠그는 DB 예산 SQL로 월 10접수·동시 1작업을 강제한다. SQL 자체 검사·호출 어댑터 연결·후속 PostgreSQL 두 연결 경쟁 검사는 통과했지만 운영 적용은 아직이다.

3D 출력은 우선 브라우저의 WebGL과 직접 작성한 도형·상호작용으로 제한한다. 외부 유료 3D 모델, 새 패키지 설치, 원격 CDN은 이 실행기에서 제공하지 않는다. 카메라 조작과 3D를 쓰기 어려운 환경의 대체 표현을 학습 설계에 요구한다. 실제 3D 결과물과 기기별 성능 검증은 별도 실행 증거가 필요하다.

## 로컬 구현

- `automation/runner/bounded-responses.mjs`: 고정 OpenAI Responses API, 토큰 수 사전 조회, 호출 전 예약과 사용량 정산, 입력·출력·시간 제한. API 키는 전송 계층에만 전달하고 도구·코드 실행·파일 입력·재시도는 제공하지 않는다. 응답을 잃은 경우 비용을 환불 처리하지 않고 불확실 상태로 남긴다. 생성 뒤 취소된 경우 사용량은 정산하고 결과 전달은 중단한다.
- `automation/runner/budget-ledger.mjs`: 신뢰된 서버의 Supabase 클라이언트를 통해 예산 RPC를 연결한다. 10초 DB 요청 제한, 작업/호출/요청 해시와 정산 영수증 확인, 원문 오류 제거. 실제 운영 DB에는 예산 SQL이 없어 아직 연결할 수 없다.
- `automation/runner/candidate.mjs`: 모델의 JSON을 실행하지 않고 해석한다. 단일 콘텐츠 ID·학년·단원·확인된 교육과정 필드를 유지하며 `draft`/`in_review`만 허용한다. 경로 이탈, Windows 장치명·대소문자 충돌, 실행파일·패키지·워크플로·설정 파일을 거부한다. 기존 자료실 방식으로 각 파일과 전체 후보 해시를 계산한다. 이것만으로 JS가 안전하다거나 실제 동작한다고 판정하지 않는다.
- `automation/runner/pipeline.mjs`: 분리된 호출 문맥으로 역할을 순차 수행하고 최대 두 번 수정한다. 원래 요구사항·출처·설계·정확한 후보·실행 증거를 검토자에게 전달한다. 실패 이력을 보존하고 해시가 다른 검토, 미실행 검사, 자료 부족을 차단한다. 최종 반환은 사람 검토용 후보이며 승인·배포 기능은 없다.

파이프라인의 `authorize`, `claimRun`, `checkpoint`, `record`, `verify`는 신뢰된 호스트가 제공하는 필수 연결이다. 기본 허용 함수나 가짜 검사기가 없다. `authorize`는 검토된 공개 입력과 AI 처리 권한을 확인해야 한다. 사용자 JSON이나 모델이 선언한 true를 권한 증거로 받아서는 안 된다. 후속 [작업 저장소 구현](WORKER_STORE.md)에서 검토된 입력의 DB 참조 확인, 한 번만 점유, 전체 예산 예약, 비공개 증거 기록 연결을 로컬 SQL로 검사했다. 자료 권한을 실제 검토하고 참조를 발급하는 UI/API와 운영 배치는 아직이다. `verify`는 API 키·쓰기 토큰·OIDC 권한이 없는 별도 검사 환경에서 수행해야 하며 실제 구현은 여전히 미연결이다.

## API 방식과 가격 근거

기존 문서는 Codex GitHub Action 실행을 계획했다. 이번 구현은 **모델별 출력 토큰과 호출별 예약 금액을 직접 제한하기 위한 Responses API 실행기 후보**다. 기존 Actions나 Codex 설정을 바꾸지 않았으며, 운영 전환을 완료했다고 기록하지 않는다. 현재 로컬 Codex에서 실제 하위 에이전트를 새로 실행한 것도 아니다. 나중에 실제 API로 수행할 때 각 역할을 이전 응답 ID 없이 별도 요청 문맥으로 실행한다.

2026-10-04 확인한 [GPT-5.4 mini 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)에 따라 `gpt-5.4-mini-2026-03-17`을 고정했다. 입력 USD0.75/백만 토큰, 출력 USD4.50/백만 토큰이다. 내부 예약은 캐시 할인 없이 더 큰 캐시 쓰기 요율까지 보수적으로 계산한다. 자동 가격 변경을 추측하지 않도록 2026-11-04 이후에는 가격 재확인 전 호출을 거부한다.

[공식 토큰 수 조회](https://developers.openai.com/api/docs/guides/token-counting)와 [Responses 생성 규격](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)을 확인했다. 입력 24,000토큰, 개발 출력 16,384토큰, 나머지 역할 출력 4,096토큰 상한이며 출력 한도에는 숨은 추론 토큰도 포함된다. 일반 서비스 등급만 허용하고 반환 모델·등급·사용량이 예상과 다르면 비용을 확정하지 않고 예약을 유지한다.

## 검사와 다음 연결

새 실행기 검사 25개를 포함한 `npm.cmd run test:studio` **67/67 통과**. 공급사 요청은 전부 모의 응답이며 유료 호출 0회다. PGlite에 실제 예산 SQL을 실행하여 호출 예약→정산→중복 거부를 연결했다. 첫 연결 검사에서는 기존 DB에 없는 `needs_review`를 사용해 실패했고, 실제 허용 상태인 `needs_input`으로 수정했다. 운영 DB 제약을 완화하거나 실패 검사를 제거하지 않았다.

검증 범위는 비용·경로·해시·수정 제한·취소·미검증 보류와 프로그램 흐름이다. 과학적 정확성이나 교육과정/교과서 대조, 3D 렌더링·학습 효과, 실제 과금·OIDC·게시를 통과했다고 뜻하지 않는다.

후속 작업 저장소·[인증 API](WORKER_AUTH.md)와 [브라우저 검사](WORKER_RUNTIME.md) 구현 이후 전체 검사97개, 실제 Chrome 합성8사례, PostgreSQL 실제 두 연결 경쟁11개가 통과했다. 브라우저 실패→모의 개발 수정→실제 재검사를 연결했지만 실제 AI 생성물·과학 검토는 아니다. 남은 실제 연결은 OpenAI API 키의 안전한 저장, GitHub App/작업 실행과 실제 OIDC 토큰 검증, 검토된 입력 발급과 소스 사용 권한 확인, DB 작업 저장소/예산 운영 적용·활성화, 키 없는 폐기 가능한 원격 검사 환경, 버전에 묶인 승인·게시·게시 확인이다. 현재 출처 목록의 교육과정·교과서와 AI 제공 허용 미확인 상태는 보존했다.
