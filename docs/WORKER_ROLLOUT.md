# 실제 제작 연결을 위한 적용 순서

2026-10-05 로컬 검증 뒤의 운영 연결 절차다. 아래 원격 작업은 아직 실행하지 않았다. 검사 코드가 있다는 사실과 실제 운영 검증을 구분한다. DB 비밀번호 갱신·접속·운영 studio 백업/로컬 복원·v2 대화 관리 SQL은 이미 완료한 작업이므로 반복 적용하지 않는다.

## 준비된 변경과 현재 제약

과제 입력/사용 동의→월 예산/작업 예약→GitHub 접수→분리된 제작/검사/보고→결과/수정 의견→새 동의를 거친 후속 제작까지 로컬 코드가 연결되어 있다. 전체 제작실151개, Chrome19개 통과 증거(17개와 수정2개 별도 재실행), 실제PG17 경쟁29개를 확인했다. 모델/GitHub/OIDC 클레임/일부 실행 보고는 합성이다. Linux Docker·실제 Actions/OIDC·유료 제작은 아직 실행하지 않았다.

현재 공개 main은4931c7e0445b2d227bac9c6ecfa29fcff62b5607이며 작업 브랜치는codex/studio-v2-budget이다. 기존40개 스테이징은 이전 승인 검토 범위이고 전체 최신 코드와 다르다. 공개할 정확한 목록/해시·기능 영향과 원문/키 제외를 확인한 뒤 변경 범위를 승인받는다. 현재 디렉터리 전체를 무조건 git add하지 않는다. 앱 변경 PR은 Vercel의 연결 설정에 따라 미리보기 배포를 유발할 수 있으므로 미리보기에는 운영 자격증명을 주지 않는다.

## 순서

1. **정확한 공개 코드 범위 확인 → draft PR.** Raph-Alpaca/science-simulations의codex/studio-v2-budget→main이다. 기존 staging 스냅샷을 보존하고 검토된 최신 파일만 반영한다. 생성 콘텐츠의 학생용 게시 승인은 포함하지 않는다. PR 생성 시 Codex task에 링크를 첨부한다.
2. **main에서 비밀 없는 rehearsal.** 코드 검토/병합 뒤 고정 SHA를 기록하고 studio-worker의기본rehearsal로 Linux Docker/Chromium sandbox·2D/3D·고장 감지·정리를 실제 검사한다. 컨테이너가 실패하면 권한을 확대하거나 sandbox를 해제하지 않는다. 정확한 실행 로그/시각/해시/종료 확인이 필요하다.
3. **운영 DB 증분 검토.** 이미 적용된v1/v2 baseline은 제외한다. 새 순서는 runner_v1→budget_v1→worker_v1→worker_auth_v1→input_review_v1→dispatch_v1→result_review_v1→revision_v1이다. 제안 파일을 적용 완료 migration으로 임의 복사하지 않는다. 현재 원격 이력과 스키마를 확인하고 새 migration을 검토·생성한다. 필요한 최신 백업/복구 범위와 현재 운영 데이터에서의 호환성을 확인한 뒤 기본 비활성으로 적용하고 RLS/함수/지문을 재검증한다. 로컬의29개 검사는 이 운영 호환 검사를 대신하지 않는다.
4. **호환 앱 배포와 보호 설정.** 실제 운영 origin·허용 교사·서비스 전용키와 기능 플래그를 확인한다. 모델/API키·GitHub App private key·DB키는 브라우저/콘텐츠/공개 Git에 넣지 않는다. 생성기에는 DB 관리자권한·쓰기 토큰을 주지 않는다. 이전 호환 앱으로 되돌릴 때 새 DB/기록을 손상시키지 않는지 확인한다.
5. **GitHub App과 OIDC 결합.** App 설치는 해당저장소만 Actions write/Contents read, 고정repository/owner ID·main/workflow SHA·attempt1 검증. App private key는 서버 전용, OpenAI 키는 generation 전용, 전송 키는 신뢰된 봉인/해제 래퍼에만 둔다. 격리 실행 컨테이너에는 어떤 키/보고 권한도 전달하지 않는다. 실제worker API와 발급/보고 역할의 권한 차단을 확인한다.
6. **제한된 첫 유료 제작.** 별도 플랫폼과 내부 월10,000원/10건 정책을 확인한다. 교사가 공개 가능한 자료/자기 요약과 정확한 과제를 확인하고 작업당1,000원에 동의한1건으로 시작한다. 실제 비용/실행번호/검사/결과를 확인하고 불확실한 비용이나 실패를 지우지 않는다. API가격 만료일(현재2026-11-04) 전에도 적용 시 최신 고정 모델/가격을 재확인한다. 준비되지 않은 원문 근거를 통과로 취급하지 않는다.
7. **후속 수정의 실제 왕복.** 정확한 결과에 수정 의견을 저장→기존 후보/누적과제/새 비용 동의→같은콘텐츠ID 후속작업→새검사/후보를 확인한다. 원래작업의 기록 보존과 오래된 결과 분기 차단, 응답유실시 한 번만 실행되는지 확인한다.
8. **게시 기능은 별도 완성/검증.** 신뢰된 원문 검토 저장소/발급자, 관리 origin 밖의 조작 미리보기, 고정 배포물·사람의 승인·PR/병합·같은 바이트 배포·실제 URL/버전/조작 확인·복구가 남았다. 현재 Pages workflow는 빈 자료실용이다. 제작실의awaiting_approval이나 AI pass를 콘텐츠 게시 승인/완료로 해석하지 않는다.

각 단계의 실제 증거와 미검증 사항을 STATUS에 남기고, 앞 단계가 실패하면 다음 활성화를 진행하지 않는다. 이미 확인한 로컬 검사를 이유 없이 반복하여 비용/사용량을 쓰지 않는다. 중단 시 예약/미확정 비용을 임의 환불하거나 실패를 삭제하지 않는다.
