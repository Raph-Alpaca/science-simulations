# 최종 시스템 명세 v3.0

## 구성
한 저장소에 공개 자료실과 교사용 제작실. Pages는 학생용 정적 파일, Vercel/Next.js는 관리 화면과 서버, Supabase는 교사 인증과 비공개 작업 기록, Actions는 긴 제작과 검사, OpenAI는 대화·제작·검토·음성.

## 흐름
문자/음성→서버 인증·인자 검증→작업+중복방지 키 저장→main의 지정 workflow dispatch→근거·교과/교육과정 검토→학습 설계→구현→독립 검토·실제 검사→최대2회 수정→정책 판정→PR/승인/반영→같은 결과물 배포→게시 확인.
작업ID·실행번호·콘텐츠ID·candidate hash·승인버전·공개커밋/URL을 연결한다. 모델 응답만으로 완료를 결정하지 않는다.
선생님은 결과를 확인하고 수정·보완을 요청할 수 있다. 해당 결과 버전에서 후속 제작·독립 검토·실제 검사를 진행하고 다시 결과를 제시한다. 최종 공개에는 선생님의 해당 버전 승인이 필요하며, 수정 요청·검토 메모·모델의 통과 판정은 게시 승인이 아니다. 자동 보완은 작업당2회이고 선생님의 후속 요청은 기존 월 예산·건수·후속 작업 상한과 비용 동의를 적용한다.

## 개인 에이전트 통합 요구사항 — 2026-10-07
향후 사용자의 개인 에이전트가 과제 접수·진행 조회·결과 검토·수정 요청·취소와 승인된 게시 절차를 호출할 수 있도록 설계한다. 웹 제작실과 에이전트 연결은 같은 서버의 업무 규칙·작업 기록·비용 상한을 사용한다. 플랫폼별 연결 방식은 교체 가능한 별도 계층으로 두고, 외부 요청의 접수와 오래 걸리는 제작 실행을 분리한다. 재연결·응답 유실 시 같은 작업을 조회하고 중복 유료 작업을 만들지 않는다.

사용자는 기반 플랫폼은 아직 미정이며, 제작·검토·수정의 자동 진행과 선생님의 수정·보완 요청, 공개 전 사람 승인을 확인했다. 현재 브라우저 세션 API와 Actions 전용 인증은 범용 에이전트용 연결이 아니다. 에이전트별 인증·위임 범위·승인 주체 기록·철회는 별도 구현/검증 대상이다. 개인 에이전트가 현재 허용 범위를 스스로 확대하거나 검사 결과·사람 승인을 대신 발급할 수 없다. 현재 운영 기능의 비활성 상태와 미구현 범위는 이 설계 결정만으로 바뀌지 않는다. 구체적 요구와 미구현 항목은 [AGENT_INTEGRATION](AGENT_INTEGRATION.md)에 기록한다.

## 자료
.local/reference의 비공개 원문을 공개 Git/로그/PR/아티팩트/dist에 포함하지 않는다. 첫 원격 자동화는 공개 출처와 공개 가능한 직접 작성 요약만 사용한다. 필수 비공개 자료에 접근할 수 없으면 보류한다. 원문 제공/재배포/AI 처리 권리는 별도 확인한다.

## 역할
교육과정 검토, 교과 검토, 학습 설계, 개발, 독립 검토. 실제 분리 실행의 입력·출력을 남긴다. 여러 모델의 동의가 정확성을 보장하지 않는다. 기계적 판정과 배포는 일반 프로그램이 맡는다.

## 보안
관리 서버만 Supabase secret과 GitHub App 키를 보관한다. 생성 코드 검사에는 API 키·쓰기 토큰·OIDC 보고 권한이 없다. OIDC 보고는 서명/issuer/audience/만료와 실제 repository_id/workflow_ref/ref/run_id/run_attempt 클레임을 검증한다. 재사용 워크플로는 job_workflow_ref도 확인한다. 앱의 job_id가 기본 OIDC 클레임이라고 가정하지 않으며, DB의 작업과 검증한 실행번호를 서버에서 연결한다. 토큰 재사용과 다른 작업에 대한 상태 변경을 차단한다. 콘텐츠 제작은 검사/워크플로/공통 코드/지침을 바꿀 수 없다. 기준 main의 검사와 허용 경로를 사용한다.

## 공개
검사·승인과 콘텐츠 버전이 같아야 한다. meta의 자기 선언으로 공개하지 않는다. 변경되면 재검사한다. 초안 파일은 배포에서 제외한다. 후보 코드를 관리 origin에서 실행하지 않는다. 공개 사이트에서 숨겨도 public Git 이력은 비공개가 아니다.

## 정책
AUTO_PUBLISH=false. 신규·수정 콘텐츠 모두 선생님이 최종 버전을 승인한 뒤 동일 산출물의 게시·확인을 자동 수행한다. 자동 제작·검토·수정 권한에 게시 승인 권한을 포함하지 않는다. 자료 미확인·새 의존성·공통 코드·권한·파괴적 변경은 별도 승인. GitHub 보호 정책과 충돌하면 멈추고 보고한다. 최종 게시 직전 취소/정책/버전을 재확인하며 승인 뒤 변경된 결과에 이전 승인을 재사용하지 않는다.

## 운영
추가·수정·중단·재공개·조회·취소·재시도·비상정지·복구·상태점검·신고·업데이트·비용·보존 정책을 제공한다. 명세만 있는 기능을 구현 완료로 표시하지 않는다.
