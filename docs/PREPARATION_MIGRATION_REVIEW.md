# 제작 전 자료 확인 DB 증분 검토

2026-10-16. **운영 미적용**. 로컬 합성 검사는 통과했고 최신 운영 백업·격리 복원 시험은 승인 대기다. 적용 준비, 실제 적용, 기능 활성화, 자료 기록 발급, 유료 제작은 각각 구분한다.

대상은 기존 science-studio의 studio 스키마다. CLI2.119.0의 migration new로 만든 `20261015234634_studio_source_preparation.sql`이며 LF SHA256은 `d2f046de8f5d59d65a1d6a7e418a5ac1f93c2e39198ec6431d8cdbb88cb6e257`이다. 검증한 proposal2개의 LF 해시와 본문을 포함한 단일 트랜잭션이다.

## 범위와 영향

- 자료 확인 기록 테이블1개, 함수10개, 트리거4개를 추가한다. 기존 함수는 교체하지 않는다. 테이블은26→27개다. 기존 데이터·첫 실행 제한·기능 비활성 상태를 보존한다.
- 서버는 자료 기록을 읽을 수 있으나 발급·수정·철회할 수 없다. 브라우저에는 테이블/함수 권한을 주지 않는다. 기록 생성과 철회는 별도 운영 권한으로 실제 원문 확인 후 수행한다.
- 새 작업과 새 API 비용 예약은 현재 유효한 자료 기록과 동의한 입력의 일치가 필수다. 기존에 접수된 입력의 중복 조회와 발생 비용 정산은 보존한다. 자료 기록의 변경은 예산 정책 행 잠금을 먼저 획득한다.
- 작업/예산/게시 기능이 켜져 있거나 진행 중인 실제 작업·미정산 예약이 있으면 적용을 거절한다. 재적용도 거절한다. 적용 과정에는 짧은 DDL 잠금이 필요하며 lock_timeout5초/statement_timeout30초를 둔다.
- 실제 자료 기록0개로 시작한다. SQL 적용만으로 제작을 활성화하지 않는다. 앱 설정 STUDIO_SOURCE_PREPARATION_ENABLED도 기본false다.

## 확인된 검사

통합 migration의 기존26개 테이블 데이터와 모든 기존 함수 정의·권한 보존, 신규 테이블 RLS/접근 차단, 기능 비활성, 중간 실패 전체 rollback, 중복 적용 거절을 합성 DB에서 확인했다. 백업/기존 실행 제한 회귀를 포함한12개 PASS. 별도 계약·저장소·접수·수정·실행기42개 PASS, 빌드·타입 PASS, 브라우저6개 PASS.

네이티브 PostgreSQL17에서 실제 연결 사이 잠금/철회/접수/예약/중복 경합6개 PASS, 서버 종료 확인. 실제 운영 데이터와 전체 복원본을 사용한 적용 시험은 아직 미실행이다. 이 한계를 운영 적용 완료로 확대하지 않는다.

## 백업 및 적용 전 조건

준비된 백업은 studio26개 테이블만 대상으로 하고 운영 연결은 읽기 전용·인증서/호스트 검증을 유지한다. 과제·대화·실행·비용·승인 등의 기록을 이 PC의 기존 보호 폴더 아래 새 preparation-preflight-20261016-* 폴더로 복사한다. 원격 Auth 데이터는 복사하지 않으며 복원용 참조만 만든다. 원문·비밀번호·백업을 공개 Git/PR/배포에 포함하지 않는다.

복원 후 정확한 migration 해시를 검사하고127.0.0.1의 새 로컬 DB에만 적용한다. 기존26개 데이터/함수 보존,27개 테이블/새 기록0,권한,모든 실행 기능 비활성을 확인하고 서버를 종료한다. 적용/복원 결과가 불명확하면 같은 작업을 자동 반복하지 않는다.

자동 승인 검토는 이번 데이터와 로컬 저장 위치의 구체적 승인이 없다며 새 백업 실행을 차단했다. 현재 승인 질문은 이 **읽기 전용 백업1회·로컬 복원·로컬 SQL 시험**만 대상으로 한다. 운영 적용·환경 변경·유료 호출·학생 게시는 포함하지 않는다. 최신 백업/복원본 시험과 읽기 전용 운영 적용 계획 확인을 통과한 뒤 실제 적용 범위를 검토한다.
