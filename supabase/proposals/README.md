# SQL 변경 이력과 적용 대기

**2026-09-15 현재:** 사용자가 v1을 적용한 뒤 실제 연결/권한 검사를 진행했다. 아래 ‘미적용’ 표와 문단은 최초 검토 당시 기록이다. 배포 준비 중 이 SQL을 다시 실행하거나 migration으로 재적용하지 않는다. 최신 검사/계정 상태는 [STATUS](../../docs/STATUS.md)를 따른다. 이번06에서는 원격 SQL을 실행하지 않는다.

| 버전 | 파일 | 목적 | 실제 적용 |
|---|---|---|---|
| studio-v1 / 2026-09-13 | studio_v1.sql | 전용 studio 스키마, teachers 및 대화·작업·검토·승인·배포7테이블, RLS/최소 GRANT, 모의 접수·전이 트랜잭션 | 미적용·구문/연동 미검증 |

이 폴더는 **검토용 변경안**이며 Supabase migration 이력이 아니다. 기존 프로젝트·스키마를 확인하고 사용자가 승인한 후 CLI의 `supabase migration new`로 실제 이력 파일을 생성한다. 기존 studio 스키마가 있으면 본안은 실패하도록 설계했다. DROP, 데이터 덮어쓰기, create or replace는 하지 않는다. 기존 데이터가 있으면 별도 비파괴 이관안을 먼저 작성한다.

teachers에는 자동으로 계정을 삽입하지 않는다. 승인된 실제 교사 UUID는 서버 환경파일과 비공개 DB에만 기록한다. 원문 요청·사용자 기록을 이 저장소의 SQL 예시·fixture에 넣지 않는다. 실제 적용 전후 검증표와 메뉴는 [설정 안내](../../docs/STUDIO_SETUP.md)를 따른다.

2026-09-13 사전 검토에서 미적용 v1안을 보완했다. command_type과 예상 버전에 중복 명령을 결합하고 재시도의 예상 버전을 검증한다. 함수 인자·EXECUTE 시그니처·서버 RPC 호출도 함께 변경했다. 전역 기본 권한에 효력이 없는 스키마별 기본 REVOKE 대신 같은 트랜잭션 안의 실제 객체 REVOKE/GRANT를 유지한다. 설치 트랜잭션에 lock_timeout 5초·statement_timeout 30초를 추가했다. 로컬 정적 계약 검사는 통과했지만 실제 PostgreSQL 실행 검증은 아니다. 상세는 [SQL 사전 검토](../../docs/STUDIO_SQL_REVIEW.md)를 따른다.
